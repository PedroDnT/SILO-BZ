## docker-compose.yml — all services

The primary compose file starts all four services (CVM API, B3 CALC API, BACEN API, and a static docs server):

```bash
docker-compose up -d
```

Services and their ports:

| Service | Port | Image |
|---|---|---|
| CVM Credit API | 8000 | `src/cvm_api/Dockerfile` |
| B3 CALC API | 8001 | `src/b3_calc_api/Dockerfile` |
| BACEN API | 8002 | `src/bacen_api/Dockerfile` |
| Docs (static) | 8080 | `docs/Dockerfile` |

Stop all services:

```bash
docker-compose down
```

## Building individual images

Each service has its own `Dockerfile` and `requirements.txt`:

```bash
# CVM API
docker build -t cvm-api src/cvm_api/

# B3 CALC API
docker build -t b3-calc-api src/b3_calc_api/

# BACEN API
docker build -t bacen-api src/bacen_api/
```

---

## compose.yaml — root image

`compose.yaml` builds the root-level `bziliquidscrapper` image:

```bash
docker compose -f compose.yaml up
```

---

## Passing environment variables

Pass a `.env` file to any compose command:

```bash
docker-compose --env-file .env up -d
```

Or set variables inline:

```bash
B3_CALC_BASE_URL=https://example.com docker-compose up b3_calc_api
```

## Persistent volumes

The following directories are created at runtime and should be mounted as volumes for persistence:

| Directory | Purpose |
|---|---|
| `cache/` | CVM file cache (keyed by URL MD5) |
| `temp/` | Temporary download files |
| `data/` | Backfill output |

These directories are listed in `.gitignore` and are never committed.

## Health checks in production

Use the `/health` endpoints in your orchestration health checks:

```yaml
# Example Kubernetes liveness probe
livenessProbe:
  httpGet:
    path: /health
    port: 8000
  initialDelaySeconds: 10
  periodSeconds: 30
```

# The portfolio report: Redator, Revisor and PDF

What turns the engine's JSON (`engine-output.md`) into the Portuguese PDF report. Code: `src/portfolio/report/`; this page is the contract between the engine and the report. One rule decides everything: **a number in the report comes from the engine, never from a model.**

```
python -m src.portfolio.report.build engine.json --out report.pdf [--html report.html] \
    [--provider fake|anthropic|openai] [--signature TEXT] [--no-llm-review]
```

`--provider fake` writes the findings with a deterministic template writer (no network, no key). `anthropic` and `openai` use the Redator and the Revisor over the provider's API. Without `--provider`, `SILO_LLM_PROVIDER` decides, and an unset variable means `anthropic`. A sample report is `docs/reference/portfolio/sample-report.pdf` (synthetic fixture).

## Roles

| Role | Does | May not |
| --- | --- | --- |
| Engine (`src/portfolio/`, SQL in schema `api`) | Every figure, with source tool, arguments and data date | Write prose |
| Redator (`redator.py`) | Writes the findings in Portuguese from the masked engine JSON, with `{{path}}` placeholders | Type a digit, date, CNPJ or amount |
| Revisor (`revisor.py`) | Removes what the engine does not support: deterministic code first, then an optional LLM pass | Add a placeholder or a claim; the LLM pass may only delete or reword, and a reword is re-checked by the same code |
| Renderer (`render.py`, `values.py`) | The one place a figure becomes text, in Brazilian format | Format by anything but the path's last key |

The Redator sees the masked JSON only: `assert_masked` refuses the call when anything that looks like the client (name, CPF, account, a forbidden key) is in it. The engine already guarantees none is: holder `[TITULAR]`, accounts `C1..Cn`.

**What the Redator sees (engine 1.7).** `redator.redator_view` deletes keys from the report's view (never list items, so every path that survives is the same path in the full view): every free-text `reason`, `error`, `errors`, request `params`/`args`, `endpoint`, the screens that did not run and the `gaps` list; `sections` keeps only `status` and `reason_codes`. So the input is portfolio facts and status codes. The Revisor checks every finding, and its LLM pass reads, against that same view, so a placeholder on an error, a param or a reason is "marcador sem caminho" and is removed. The prompt says findings are about the portfolio, never about the pipeline (a failed call, a section not evaluated, an unidentified line, a missing fee); that the same asset on two statement lines is already merged and is not a finding (nor a shared exposure with `same_position`); and that zero findings is a valid answer. A draft with no findings is a complete narrative; only a draft whose every finding the Revisor removed is `revisor_removed_all`.

**What could not be assessed is not the Redator's.** "O que não foi possível avaliar" is a fixed section built from the view's `gaps` (`adapt.py`), one short line per gap with a fixed Portuguese text per reason code (`common.REASON_TEXT`): the unidentified lines grouped by reason with their value, the funds identified by the statement's CNPJ only, the fee lines without a usable fee grouped by status, the screens that did not run, the funds with no movement verdict, the other sections' codes. No raw error, PostgREST body or request param reaches the page: the view's `provenance` has no `params` or `error`, and a narrative that failed prints a fixed sentence (its error class stays in `reason_code`, for the `X-Silo-Narrative-Reason` header). The Revisor's notes (what it removed and why) stay in the `Narrative` object for logs and JSON; the PDF has no "Notas do Revisor".

## The placeholder rule

A placeholder is `{{path}}`: dot-separated keys with `[i]` list indexes into the engine JSON, for example `{{fees.by_line[3].estimated_pct_year}}`. A sentence with a literal digit outside a placeholder is removed. A placeholder pointing at a missing key or a null is removed with its sentence. The renderer prints the value by the last key of its path (the table lives in `values.py`):

| Key | Unit in the engine JSON | Printed as |
| --- | --- | --- |
| contains `_brl` | reais | `R$ 1.234,56`, `R$ 187,3 milhões` |
| contains `_pct` | percent (1.65 = 1,65%) | `1,65%` |
| contains `cnpj` | 14 digits | `00.000.000/0000-00` |
| `month`, `competencia`, ends `_month` | ISO date, first of month | `08/2026` |
| ends `_pp` | percentage points | `-0,43 p.p.` |
| `pct_of_cdi` (engine 1.13) | percent of the CDI | `97,05% do CDI` |
| other ISO date | `YYYY-MM-DD` | `31/08/2026` |
| ISO timestamp | UTC | `03/10/2026 13:00 (UTC-3) (16:00 UTC)` |
| `old_num`, `new_num`, `change_brl` of a `VL_*` leaf | reais | as `_brl` |

A fraction (`weight_in_line`, `similarity`, `explained_weight`) is never printed as a percent: the engine names a percent `_pct` and a fraction never. The one place a fraction becomes a percent is the exposure-origin flow diagram (see Charts, below): its text is fixed text the chart renders from `format_value` paths, not Redator prose, and `adapt._origin_segment` derives `weight_in_line_pct` as the engine's `weight_in_line` times 100 (owner's Q44 recommendation: print percent), so the chart prints "16,59% do fundo" through a `_pct` path; the Redator never sees that key (`exposure_origin` is in `REDATOR_DROP_KEYS`), so no prose can print a fraction as a percent.

## Revisor rules

Deterministic, sentence by sentence:

1. every placeholder resolves to an existing path with a non-null scalar;
2. a sentence with a literal digit outside a placeholder is removed;
3. every citation is an `id` of the engine's `provenance`, and a source named in the text (CVM, BCB, B3, FNET, ANBIMA, IBGE) is one the provenance carries;
4. an extreme value stays only when the engine carries a second path confirming it, else the sentence is removed with a note. Thresholds (`revisor.py`): a fee above 5% a.a., an exposure above 50% of the portfolio, a delinquency change above R$ 100 milhões;
5. unusual movement (`movement`, engine schema 1.3): the text may cite the "forte" level (the funds not evaluated are a gap, listed by the fixed section since 1.7); a sentence that cites the table or puts "atenção" in a sentence about movement is removed, because "atenção" is a table-only level. Movement paths are exempt from the exposure rule.

6. main risks (`risks`, engine schema 1.8): a sentence that cites a row with `text_allowed` false (its severity set only by the movement section's attention level) is removed, and so is one that cites the `movimento_anormal` row's `severity_label`, since "atenção" there is the table-only movement level. The fee coverage (`coverage_*_fund_value_pct`, `fund_value_*_pct`) is a share of the value held in funds, not a fee rate or an exposure, so rule 4 does not apply to it.

7. returns, tax and the market equivalent (`returns.`, `tax.`, `equivalents.`, engines 1.10, 1.11 and 1.13): a past return, the CDI, a class percentile, a volatility, a drawdown or a legal tax rate is not an exposure, so rule 4's exposure threshold does not apply; a fee rate there (`fee_pct_period`, `tax.lines[i].fee.*_pct_year`, `equivalents.lines[i].etf.fee_pct_year`) keeps the fee threshold.

8. "% do CDI" (engine 1.13, #606 addendum Q36): it exists only where the engine wrote `returns.lines[i].windows[j].pct_of_cdi`, for a fund whose own filed benchmark is CDI or DI. The renderer prints that placeholder as "97,05% do CDI", so the phrase is never the writer's. A `pct_of_cdi` placeholder that is null ("nulo": a share, a fund with another benchmark), whose window does not say `cdi_like` true, or that is not a key the engine writes ("sem caminho") is removed with its sentence; so is a literal "% do CDI", "por cento do CDI" or "percentual do CDI" in the text, and any placeholder other than `cdi_pct` followed by "do CDI" (it would print a "% do CDI" the engine never computed).

A finding whose title fails, whose citations are invalid or empty, or that has no sentence left is removed whole. The report states no forecast and no recommendation. What the engine does not assess is written as such, in the tables and the fixed gaps section: a restatement is "reapresentado, não avaliado"; a fee not found is "taxa divulgada não encontrada"; an estimate is "estimativa, não divulgada"; a fund without a movement verdict is "não avaliado". Concentration (engine 1.7, section "Concentração e vencimentos"): the issuer of direct credit is "emissor como impresso no extrato; grupo econômico não avaliado"; the FGC check is "a conferir: limite por CPF e instituição; o extrato consolidado pode ter mais de um titular", with the rule cited; neither is a verdict. The Redator may not turn an estimate into the fee or a performance-fee text into a rate. When the Extrato files 0 or above 5% a.a., the other document's fee is shown beside the headline (engine 1.4: `lamina_beside_*`, "lâmina informa X; a conferir", or, when the newer lâmina is the headline, `extrato_beside_*`, "Extrato de <data> informa X"). With the lâmina beside an Extrato headline, neither value is summed or compared. When the newer lâmina is the headline, its fee is summed and compared like any disclosed fee (engine 1.5, owner's decision of 2026-10-03), the line stays "a conferir" with `sources_differ_label` ("fontes divergem"), and the Extrato's value beside it is never summed. `scale_flag_label` ("possível erro de escala no Extrato") is a flag, never a correction. ETFs also carry a fee (engine 1.5): CVM's documents hold none for an ETF, so the line shows the fee etfsbrasil.com.br prints, with its date, labelled `etf_site_label` ("taxa informada pelo site etfsbrasil.com.br (fonte de terceiros, não é documento da CVM)"); the text never calls it a CVM-disclosed fee, and it is summed apart (`fees.total_etf_site_brl_year`, and with the disclosed fees in `fees.total_fee_brl_year`). Each ETF line also shows the site's cotistas and PL of the same snapshot (engine 1.6: `etf_site_nr_cotistas`, `etf_site_pl_brl`, with `etf_facts_label` and `etf_site_as_of`), written only through placeholders, credited to the site with its date, and never summed or used as a fee base. Fees by level follow Res. CVM 175 Art. 98 (`docs/reference/research/cvm175-structure-and-fees.md`): a fund-of-funds' disclosed administration and management fee already includes its investees' unless the investee is listed or run by an unrelated manager, so the report never adds a master's fee to a feeder's in that case.

## Principais riscos, the fee headline and the charts (engine 1.8)

"Principais riscos" and "Quanto a carteira paga em taxas" follow the summary. The risks table prints every row of `risks.rows` with its value, semáforo (atenção, moderado, baixo), fixed explanation and thresholds; a row the engine could not evaluate says "não avaliado" with its fixed reason and is also listed in "O que não foi possível avaliar". The methodology prints every threshold. The Redator's section `riscos` holds at most three short findings on the evaluated rows with the highest semáforo, in table order, through placeholders only; the prompt forbids recommending a purchase, sale, holding or diversification, saying what the investor should do, and forecasting markets, rates, inflation or returns. The Redator does not see `table_only` (the attention-level movement count), `tree` (the look-through diagram's selection) or `exposure_origin` (the exposure-origin chart's data): `REDATOR_DROP_KEYS`. The fee headline prints the disclosed fixed total in R$ a year and as a percent of the portfolio, the range and the ETF site fee apart (labelled as third-party, never added to the disclosed total), the coverage, the balancete estimate apart, and the "não incluído" list.

Charts (`charts.py`) are static inline SVG, drawn in Python with literal colours and no JavaScript or external fetch, so weasyprint renders them: allocation by class and by indexer ("sem classificação" a gray bar of its own), maturity by year, top direct-credit issuers as printed, top fund positions, the look-through tree (portfolio, funds, largest underlying assets) and the fee cost per fund in R$ a year (an ETF site fee an outlined orange bar with its own legend). A further chart, "De onde vem a exposição ao mesmo ativo" (owner's decision Q42 = A, 2026-10-05; redrawn on 2026-10-06 as an arrow flow diagram because the stacked bar did not say which statement line was which), sits under the "Sobreposição" table: one diagram, and one figure, for each of the five largest `mesmo_ativo` groups of `look_through.shared_exposure` (by `total_exposure_brl`; an asset in one line is not a group). Left to right: a box for each statement line that holds the asset, with the line's own name first (`linha_extrato`) and under it "linha N · type · posição R$ x" (`tipo` and `valor_brl` of `statement.positions[]`, matched by `line_no`; a missing value is left out, never guessed) and a small tag, "direta" or "via fundo"; a smooth ribbon from each box to the asset, with an arrowhead at the right end, whose thickness is that line's `exposure_brl` (largest first, no crossings; geometry only, proportional within the diagram, with a minimum so a small slice stays visible); and the asset's box with its code and ISIN (the group `label`), the engine's `total_exposure_brl` and `total_exposure_portfolio_pct`. The text above each ribbon is "direta: R$ x", or "via fundo: 16,59% do fundo = R$ x" and then "CDA 05/2026 (4 meses antes do extrato)" (the CDA month and its age against the statement's `position_date`); a fund that holds the asset through several paths prints "N caminhos dentro do fundo (peso não somado)" instead of a weight. The weight is a percent here, the one place a fraction is shown as one (see "The placeholder rule": `weight_in_line_pct` is the engine's `weight_in_line` times 100, taken in `adapt.py`; the chart text is fixed text, not Redator prose). `adapt.py` computes three figures for this chart and no other: `cda_age_months` (two engine dates subtracted by calendar month), that percent, and, for an asset with more than six lines of positive exposure, the count and R$ sum of the lines past the five largest (`overflow`: the drawn ribbons, the overflow row and the lines listed as text together add up to the total to the centavo, and the segments in the view always do); a weight under 0,005% prints as "menos de 0,01%", never "0,00%". The weight and month are copied from the line's `look_through.lines[].exposures[]` rows for the asset, and only when those rows add up to the group's value for the line to the centavo. A line with zero, negative or missing exposure gets no ribbon and is listed as text under the diagram; with more than six lines the five largest are drawn and one row says "+N linhas menores: R$ x". Under each diagram sits the same fixed caveat: the via-fund part is the fund's portfolio in the CDA month and not at the statement date, a fund with no CDA for the month is not opened so the total is a floor, ON and PN shares of one company are different assets here, and the ribbon thickness rule, followed by the engine's own `shared_exposure.note` (while `economic_group_assessed` is not true) and the fixed text of the `sem_carteira_cda` code when the engine carries it. Each diagram has an `aria-label` and a `<title>`, and no text is smaller than 7.5 px. It is plain inline SVG drawn by hand: no charting library, because weasyprint has no JavaScript (so Plotly cannot render in the PDF) and the engine image installs only `deploy/cloudflare/engine/requirements.txt`. The data is `lookthrough.exposure_origin` in the view, built by `adapt._exposure_origin`. Each chart sits next to the table it draws and never replaces it, and every label it prints is `format_value` of the same view path the table prints. A chart without data is not drawn, and the gaps section says why.

## Direct credit, managers and liquidity (engine 1.9)

The identification table marks a line with fixed badges: "lido por OCR", "código não conferido", "taxa não conferida" and "vencimento diverge do registro CVM". A "Crédito direto" table follows it for every CRA, CRI and debenture: the issuer as printed, both maturities and rates (statement and CVM registry), the registry's situação and rating as filed, and for a debenture the ISIN, the B3 issuer code, the number of funds that hold it and their mark beside the statement price, with the dates; the note says the gap is information, never a price verdict. Two charts join the others: the largest managers by filed `gestor_id` (never by name) and the liquidity ladder (D+0 a D+5, D+6 a D+30, acima de D+30, lock-up, fundo sem prazo, crédito direto, Tesouro, bolsa, caixa, sem classificação), with the redemption days as filed and never converted between business and calendar days. The four new risk rows and the evaluated `liquidez` row reach the Redator like the others, through placeholders only; the Revisor's rules do not change.

## Returns, tax and ETF fee peers (engines 1.10 and 1.11)

"Retorno por posição" prints, per line and window (12 and 6 months, the 6 not annualized), the net return, its basis, the CDI over the same dates and the difference in percentage points, the annualized volatility with its noise note, the largest drop between month-ends with its months, the fee per point of estimated gross return (a value with the gross at or below zero is marked "fora de qualquer média ou ranking") and the Sharpe the fee takes, or the engine's "não aplicável" note below 1% a.a. of volatility. A line not evaluated shows the fixed text of its code, and the lines are also grouped in "O que não foi possível avaliar". There is no portfolio total, mean or ranking. "% do CDI" (engine 1.13) is printed under the difference only where the engine wrote `pct_of_cdi`: a fund whose own filed benchmark (the Extrato's performance-fee index or the lâmina's INDICE_REFER) is CDI or DI by the spelling list of `src/portfolio/rules/benchmark_cdi.yaml`, with a CDI above zero; a fund without one shows the fixed reason beside the difference, and the report computes no figure.

"Taxa e imposto por posição" prints, per line, the fee paid a year (the fee block's headline, "estimativa"; a range as two ends), the rate in force with its article, "isento" with its article, or the bracket text; the tax in R$ only when the engine computed it (`tax.estimate.tax_brl`, "estimativa", with the rate and the 12-month gain), else the bracket or the fixed reason; and the "a conferir" items. PGBL and VGBL lines get the regressive and the progressive regime in two columns, neither picked, with the base of each plan and the irrevocable option. The optimization facts (next bracket, gross-up equivalence, come-cotas) carry "informativo; não é recomendação"; IOF appears only when the engine has it; dividends, JCP and the minimum tax are flags at the person level, never a figure. There is no portfolio total of tax. A `sem_regra` line says why in its row and in the gaps section.

The fee-peer comparison also prints the peer group split into funds and ETFs (`n_fund_peers`, `n_etf_peers`, catalog v66), with the ETF tickers and the third-party source of their fee, labelled "informativo, não é recomendação"; when an ETF is a peer, a mark says the median, quartiles and percentile include it with a third-party site fee (catalog v66 computes them over funds and ETFs together).

"Equivalente de mercado" (engine 1.13, #609) follows the tax section. Every fund with an equivalent gets one row per window: the fund, the ETF (ticker, name, index, PL and fee with their dates and the third-party label, "sem proventos" and its price basis), the fund's net return, the ETF's return, and the class's p25, median and p75 with the number of funds, each return with its position in the distribution ("entre a mediana e o p75 da classe"), labelled "posição na distribuição da classe, não um ranking". The section opens with "equivalente de mercado; não é recomendação". A fund with no equivalent is listed with the fixed text of its code, and the same lines are grouped in "O que não foi possível avaliar".

The Redator has three more sections, `retornos`, `impostos` and `equivalentes` (1.13), through placeholders only. The prompt forbids a portfolio return or tax total, a mean, median or ranking across lines, choosing a pension regime or plan, an imperative verb and the word "economia"; an optimization fact goes with its label. "% do CDI" only through `pct_of_cdi` where it is not null, never with "%", "do CDI" or "por cento" typed beside it. In `equivalentes` the ETF and the fund are set beside the class's median and percentiles, always with "equivalente de mercado; não é recomendação", the third-party label and date of the ETF's PL and fee and its "sem proventos" note; never "melhor" or "pior", never a ranking, a swap or an instruction. Window paths are `returns.lines[i].windows[j]` and `equivalents.lines[i].windows[j]` (`j` 0 is 12 months, 1 is 6).

## Structured output and validation

The Redator's and the Revisor's replies are Pydantic v2 models (`FindingsOutput`, `VerdictsOutput`). The same models define the schema each provider is asked for and validate every reply, whatever provider produced it. A reply that fails validation raises `LLMValidationError`: in the Redator the narrative is marked unknown, like a refusal, and the engine tables still print; in the Revisor the deterministic result stands. A finding with an unknown section fails the whole reply.

## Providers and the cost cap

`llm.py` is one `complete(system, user, schema)` interface with three providers, chosen by `SILO_LLM_PROVIDER`:

| Provider | Model | Key | Notes |
| --- | --- | --- | --- |
| `openai` (current, owner's choice 2026-10-04) | `SILO_LLM_MODEL`, default `gpt-5.1` (gpt-6-luna until 2026-10-04: the key gets 403 `model_not_found` on every gpt-6 model; gpt-5.1 is deprecated, shutdown 2027-04-01) | `OPENAI_API_KEY` | Responses API with structured output; reasoning effort `SILO_LLM_EFFORT`, default `medium` (`off` sends none), overridable per role by `SILO_LLM_EFFORT_REDATOR` and `SILO_LLM_EFFORT_REVISOR`; `store=False`; no hosted tools (web or file search are reserved for the later Investigator) |
| `anthropic` | `SILO_LLM_MODEL`, default `claude-opus-5-5` | `ANTHROPIC_API_KEY` | Messages API with structured output; `SILO_LLM_EFFORT`, `SILO_LLM_FALLBACKS` |
| `fake` | none | none | Deterministic, for tests and offline runs |

`SILO_LLM_MODEL` is shared by the providers: unset it, or set an OpenAI ID, before switching to `openai` from a Claude ID. The key is read from the environment only, passed explicitly and never logged.

Cap: US$ 1,00 per report, counted from the reply's token usage with a worst-case check before each call. Prices are the table in `llm.py`, read from each provider's official pricing page and dated there (for example `gpt-5.1` at US$ 1,25 input, 0,125 cached input, 10,00 output per million tokens, read 2026-10-04; it has no cache-write price, so written tokens are priced as input). An unpriced model is booked at the most expensive row, so the cap errs high. A refusal, a truncated or filtered reply, a validation failure or the cap marks the narrative unknown, and the engine tables still print. Not handled yet: an HTTP error from either SDK (a 429 for an account without credits, a 404 for a wrong model ID) still stops the run.

Swapping vendor means writing one provider class: the engine, the placeholders, the Pydantic models and the Revisor do not change.

## PDF

WeasyPrint (CSS paged media), chosen over a headless browser for one native dependency (pango and cairo) and print CSS kept as plain text in `templates/report.css`. Report-only dependencies (`anthropic`, `openai`, `pydantic`, `weasyprint`, `pypdf`, `reportlab`) are in `requirements-report.txt`, not `requirements.txt`: the daily ingest installs the latter and must not need pango. The signature defaults to the owner's ("Pedro Todescan, pesquisador independente"), overridable with `SILO_REPORT_SIGNATURE` or `--signature`.

## Hosting

The report is meant to run in the Cloudflare Container behind the upload page (slice E of map #510). The first safe deploy (`deploy/cloudflare/`, `.github/workflows/deploy_cloudflare.yml`) serves a health-only container with no engine and no LLM key. Running the report there will need `api.openai.com` in the egress list and `OPENAI_API_KEY` handed to the container; `docs/reference/research/cloudflare-container.md` was written for `api.anthropic.com`.

## Not verified

No live model call has been made with either provider; the sample report comes from a synthetic fixture. The engine schema the report reads is `engine-output.md`.

## Brief and client constraints

See [brief-client-fit.md](brief-client-fit.md). The additive `client_fit` field records declared constraints and deterministic maturity/cash checks; it never approves suitability. The brief reuses checked findings, and HTML delivery skips PDF generation until the browser print/save request.

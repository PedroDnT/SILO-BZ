Owner request of 2026-10-03, under map [#510](https://github.com/PedroDnT/SILO-BZ/issues/510).
Read on 2026-10-03, 17:30 to 18:25 UTC-3 (20:30 to 21:25 UTC). Read-only. The Base dos Dados
(BD) repositories were cloned from GitHub and read at fixed commits. BD's and CVM's web pages were
read through the Parallel fetch tool. SILO's side comes from this repository at `origin/main` on

The question is whether BD is useful as a **reference** for how to ingest CVM fund data. Using
BD as a **source** is out of scope: SILO keeps reading CVM directly.

## Answer

1. **BD covers less of CVM's fund data than SILO does, and only the ICVM 555 / FI family.**
   `br_cvm_fi` has six tables: informe diário, CDA, `cad_fi`, extrato, perfil mensal and
   balancete. It has nothing for FIDC, FII, FIP, FIAGRO, securitizadoras, the lâmina or the CVM-175
   `registro_*` files. Two more `br_cvm_*` datasets sit in the repo: portfolio-manager registry and
   public offerings. The one thing BD covers that SILO does not is **CDA blocks 3, 5, 7 and 8**,
   because BD reads all eight blocks into one long table. BD also keeps the **account-level
   balancete**, which SILO retired in migration 62 in favour of the summary.
2. **Its cleaning would break SILO's integrity rules in several places, so none of its code
   should be copied.** Every cast is `SAFE_CAST`, which turns a value it cannot parse into NULL
   without any count. Free text and codes are lowercased with accents and punctuation stripped,
   which merges ratings `AA+` and `AA-` into `aa`. Commas become dots in every column. Two
   string-to-integer casts also mangle values:
   - CDA quantities go through `replace(x, '.0', '')` and then `INT64`. On the value shape CVM files,
     `186168.000000` becomes `18616800000`.
   - The issuer CPF/CNPJ goes through the same `INT64` cast, so a formatted value becomes NULL.

   This is arithmetic on BD's code. BD's published tables were not queried (section 9).

3. **CVM 175 handling is column aliasing only.** `CNPJ_FUNDO` and `CNPJ_FUNDO_CLASSE` both map to
   `cnpj`, and `TP_FUNDO` and `TP_FUNDO_CLASSE` both map to `id_fundo`. Three CVM-175 changes are
   not handled:
   - `ID_SUBCLASSE` is not read in the informe diário.
   - None of the `registro_*` files is read.
   - The `cda_fie_*` file (FIIM, FIDC and FIAGRO holdings since 2025-11) is excluded by the block
     filename filter.
4. **Three things are worth taking as reference** (section 6):
   - BD's own written observations on CVM's publishing behaviour: mtimes regress, and the current
     month is first published partial.
   - BD's union column list for CDA blocks 3, 5, 7 and 8, as a checklist to verify against CVM's
     dictionary.
   - BD's typed column inventory for perfil mensal, as a dictionary for the columns SILO keeps in
     `raw`.
5. **Licence.** The pipelines repo declares `GPL-3.0` in `pyproject.toml` and ships no LICENSE
   file. The SDK is MIT. CVM's data is ODbL. Copying pipeline code would bring GPL-3.0 terms;
   re-deriving facts from CVM's own dictionaries does not raise that question.

## 6. Worth copying as reference

Each item is a suggestion for the owner, not work started. Discovery is not prioritization

1. **The partial-month observation, set against SILO's daily window.**

## 7. Not worth copying

Each of these breaks a SILO rule (`AGENTS.md`, "Data integrity rules"):

| BD practice                                                                              | Rule it breaks                                              |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `SAFE_CAST` everywhere, so a failed parse becomes a NULL that nothing counts             | rule 4: a failing row is dropped and counted, never coerced |
| `replace('.0','')` then `INT64` on quantities and the issuer CPF/CNPJ                    | rules 3 and 4: values must be what the source filed         |
| `limpar_string` on codes, ratings, tickers and free text; commas to dots in every column | rule 3: provenance (and BD's own style manual)              |
| One CDA table across all blocks with no natural key; `append` by partition path          | rule 5: a named UNIQUE constraint per table, upserted       |
| File selection by directory mtime                                                        | SILO's competence-driven window (section 6, closing note)         |
| `FLOAT64` money                                                                          | SILO uses `NUMERIC`                                         |
| Rename by position (manager registry)                                                    | `field_maps` map by header name                             |

Cadence is not a reason to copy BD either. BD runs once a day after the fact and polls on mtime;
SILO's daily run already covers the same files.

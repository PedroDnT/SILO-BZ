| 2026-10-05 | feat/diagnosis-traces-r2 | **Each portfolio diagnosis now writes a trace of its run to the private R2 bucket `silo-diagnosis-traces` (ADR 0003, owner decision).** The trace is OTLP/JSON following the OpenTelemetry GenAI semantic conventions, pinned as `GENAI_SEMCONV` in the new `src/portfolio/trace.py`: a root `invoke_workflow diagnosis` span (status, failing stage, files, formats, bytes, engine revision, the SHA-256 of the PDF and of the engine JSON), `engine.run` (section statuses, reason codes, identification counts) and `invoke_agent redator` / `invoke_agent revisor` (provider, model, token usage, cost; each Revisor removal is an `app.revisor.removed` event with a fixed rule code, the section and the SHA-256 of the removed text). An error is span status ERROR with the exception type only. The masked engine JSON and the PDF are separate objects named by their SHA-256. The uploaded statement is never stored, and holder, CPF and account are already masked by the readers. The engine keeps the run's bundle in memory and names it in `X-Silo-Trace-Id`. After answering, the Worker reads it once with `GET /trace/<id>` (bearer token) inside `waitUntil`, writes the objects and only then stops the instance; the header never reaches the client. `CostMeter` calls now carry `ended_unix_nano` for the agent spans. The deploy workflow creates the bucket when missing, and after the marked privacy probe finds that run's trace and fails if the marker or the upload's bytes are stored. The upload page now says what is kept. ADR 0001 is amended by ADR 0003; `feedback/<trace_id>.json` is reserved for human labels. |

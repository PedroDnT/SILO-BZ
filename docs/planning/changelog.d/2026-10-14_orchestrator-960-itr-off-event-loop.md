| 2026-10-14 | orchestrator/960-itr-off-event-loop | **The ITR/DFP ingest no longer blocks the event loop (#960).** `ingest_cia_itr_dfp` and `ingest_cia_itr_dfp_new_versions` awaited the ZIP download, then unzipped, parsed and upserted every member on the loop. The parse is synchronous and the upserts are psycopg2, so a 2.2M-row ITR year held up every other CVM slice for minutes. In run 38519970263, several small slices finished within 4 s after `cia_aberta/itr 2026` ended. Each method now awaits the download, then runs the member loop in a worker thread through `_store` (`asyncio.to_thread`), the path the FI monthly ingests already use. It is still one pass over the lazy iterator, so peak memory stays one member. The return values, the suspicious-empty warning and the audit row are unchanged, and an exception in the thread still reaches `_audited`. `_PgClient` is a `ThreadedConnectionPool` behind a semaphore, so the upserts are safe from the thread. Offline tests in `tests/test_cia_financials.py` run slow fake upserts and check that a ticker coroutine keeps counting during the ingest, and that a failure in the thread is recorded. |

| 2026-11-03 | claude/1059-api-v2-cursor-tiers | **API v2: one cursor on every list kind, and tier page sizes in `silo-api` (#1059, epic #1052).** `limit` is now the page size on every resource: its default is the tier's page maximum, and a larger value is coerced to it (`meta.limit_coerced_from`). Every registry plan declares how it pages: `p_after` (the five functions with an SQL cursor), `date_window` (split `from`..`to`, halve a window the SQL refuses for its row cap), `view_offset` (order + limit + offset) or `single_page` with a stated reason; a pytest checks every plan. `next_page_url` carries one unsigned base64url cursor that holds every original parameter and the position; a cursor with a different parameter is `bad_request`, and its content is validated again like a fresh request, so it cannot widen a tier. The tier numbers (#1061) live in one block in the new `config.ts`: no Bearer is anonymous, any other Bearer is signed in (the JWT is not decoded; pro and the per-minute limit are #1064). A walk that reaches the tier's rows-per-call cap stops with `meta.tier_cap_reached`. Daily-data plans read at most the tier's window; `screens` and `portfolio` are refused for anonymous callers; `panel` ids above the tier are refused. Deno tests were run under Bun with shims, not under Deno. No SQL changed; nothing deployed. |

| 2026-11-26 | orchestrator/1121-perfil-day1-rows | **The investor-profile ingest no longer invents a date, and a script removes the day-1 leftovers (#1121).** `cvm_fi_perfil` stores the date the source publishes, the last day of the month, and its key is `(cnpj, period)`. `ingest_fi_perfil` stamped a row with no parseable `DT_COMPTC` with the first of the requested month, so an early file version left 9,204 rows on day 1 (9,199 in 2026-09, 5 in 2026-08) beside the month-end rows a later file brought. The fallback is gone: such a row is dropped, counted and logged, as the CDA path does. Nothing is re-keyed to day 1, so the other 1.15 million rows and what the dashboard reads do not change. New `scripts/drop_perfil_day1_twins.py` is the repair, for the owner to run after re-ingesting 2026-08 and 2026-09: month by month, it deletes a day-1 row only when the same fund has a row on another day of that month, prints the row count before and after, lists the day-1 rows with no twin and counts the fund-months with rows on 2 or more other dates (62 in 2025) without touching either. It reports only unless `--apply` is given, and a second run deletes nothing. 15 offline tests; the script's SQL runs in them against an in-memory table, and ran once against a throwaway local Postgres 16. Nothing ran against production. |

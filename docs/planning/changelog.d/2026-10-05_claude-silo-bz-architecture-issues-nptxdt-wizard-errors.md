| 2026-10-05 | claude/silo-bz-architecture-issues-nptxdt | **The two owner-run setup scripts show the Postgres message when a login test fails.** `scripts/setup_agents_wizard.sh` (stage 1) and `scripts/rotate_db_password.sh` (stage 2) swallowed psql's error and said only "could not connect"; they now print the first line of the Postgres message and the usual cause (wrong password, wrong pooler user or host, mistyped host, malformed URL). libpq's connection errors carry no password, but a bad percent-encoding quotes a piece of the URL, which may be part of one, so that one message is replaced and cannot leak part of a password. `rotate_db_password.sh` also no longer needs the old URL in `.env` to be perfect: it reads only the scheme, user and host from it, so quotes, a stray space and an old password with an unencoded `/`, `?`, `#` or `@` no longer stop it, and a value that is not a `postgresql://` URL gets a plain message; the Sentinel wizard trims quotes and spaces from `SUPABASE_POOLER_URL` before it connects (psql reads a quoted value as a database name and looks for a local server). |

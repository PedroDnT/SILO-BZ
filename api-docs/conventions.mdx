### Overview

This page is the contract. The auth tiers, the 1,000-row cap, the unadjusted-price rule, the no-fill rule and the FIDC regime break are written **here and nowhere else** — every other page links to these anchors.

The machine-readable twin is `POST /rpc/catalog`: same numbers, same rules, parsed rather than read.

### Base URL

```
https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1/
```

The live Supabase Data API for this project (schema `api`). Views are `GET /<view>`; functions are `POST /rpc/<function>`.

**Note**: `/v1/*` paths belong to `serve/app.py`, a local Flask adapter that is not necessarily running anywhere. It is not the public API.

### Authentication

Send the project's **publishable** key (`sb_publishable_…`) on the `apikey` header.

```
apikey: sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437
```

The publishable key is not a JWT — do not put it in `Authorization: Bearer`. That header is for a *user* token, which is what moves you to the authenticated tier. Never use the **Secret** / `service_role` key.

<Warning>
  **The printed publishable key is shared.** It is a project identifier, not your identity — anyone reading these docs has the same one.
</Warning>

Sign in with GitHub at [silo-bz-deloslabs.vercel.app/signin.html](https://silo-bz-deloslabs.vercel.app/signin.html) and send the token as `Authorization: Bearer <token>` *alongside* `apikey`. That raises four ceilings:

| | anonymous | signed in |
| --- | ---: | ---: |
| `panel` ids per call | 3 | 50 |
| `panel` universe mode (no ids + a family) | — | yes |
| `search_funds` rows | 25 | 200 |
| `option_chain` rows | 200 | 2,000 |
| `option_exercises` rows | 500 | 5,000 |
| `fund_holdings` rows | 500 | 5,000 |
| `fund_debentures` rows | 500 | 5,000 |
| `fidc_cedentes` / `fidc_sacados` / `fidc_portfolio` rows | 500 | 5,000 |
| statement timeout | 3s | 8s |
| **rows per response** | **1,000** | **1,000** |

- **Rows per response never change.** `db-max-rows` is server-wide; no tier raises it.
- **Exceeding an id ceiling is an error, not a trim.** `22023` (HTTP 400) naming the limit.
- **The token lasts about an hour, and expiry is silent.** You do not get a `401` — you drop back to the anonymous tier. A four-id `panel` that worked an hour ago starts raising `22023` on the id ceiling.

#### What is not reachable

Landing tables (`cvm_*`, `b3_cotahist`, `cia_*`, `bacen_*`) carry no grant for either role. `Accept-Profile: public` returns `401`, not rows. Schema `api` is the whole public surface; ingest is not exposed at all. The authoritative list for the server you are talking to is `catalog().postgrest`.

**Note**: if the project exposes more than one schema and `api` is not the default, add `Accept-Profile: api` to GET and `Content-Profile: api` to POST.

#### Filter syntax

| Form | Meaning |
| --- | --- |
| `select=a,b,c` | Project columns. Omit for all columns. |
| `col=eq.VALUE` | Equal |
| `col=gte.2024-01-01` | Greater than or equal (also `gt`, `lte`, `lt`, `neq`) |
| `col=in.(A,B)` | One of |
| `col=is.null` | Is null (`not.is.null` to negate) |
| `order=col.desc` | Sort (`.asc`, plus `.nullslast`) |
| `limit=100&offset=100` | Page |
| `Prefer: count=exact` header | Add a total row count to `Content-Range` |

The same operators work on an RPC result (`POST /rpc/fund_nav?select=period,nav&order=period.desc`). They apply **after** the function's own cap.

#### Function arguments

Argument names are the SQL parameter names (`p_ticker`, `p_from`, `p_metrics`). An unknown name fails `PGRST202` — the function is matched by its argument set, so a typo looks like a missing function.

- **Omitting an argument is not the same as sending `null`.** Defaults apply only when the argument is absent. `"p_from": null` makes the comparison `BETWEEN null AND …`, which matches nothing. The one exception is `p_board`, where explicit `null` means "all boards".
- **An unrecognised `panel` metric is ignored, not rejected.** The panel comes back smaller and plausible. Take names from `catalog().metrics`.

### Dates, ids, and case

- Dates are ISO `YYYY-MM-DD`. Ranges use `BETWEEN` — **both ends inclusive**.
- Tickers are upper-cased and trimmed server-side, so `petr4` works.
- CNPJs are stripped to 14 digits, so `12.345.678/0001-90` and `12345678000190` are the same input.
- In `panel`, an id with exactly 14 digits after stripping is a CNPJ; anything else is a ticker. There is no separate parameter.
- Monthly grains key on the **first day of the month** in `panel`. `fund_nav` returns CVM's filed period, whose convention is per family (`fidc` files month-end, `fip` files 31-December annually).

### Row caps

<Warning>
  **The binding cap is 1,000 rows, and it is not in the SQL.** PostgREST is deployed with `db-max-rows = 1000`.

  - **GET views truncate** — cut to the first 1,000 (the **oldest**) rows, returned as `200`. A cut series looks like a series that ended.
  - **`POST /rpc` functions refuse** — every set-returning function raises `22023` rather than hand back a slice that looks whole.
</Warning>

| Endpoint | Above one 1,000-row page |
| --- | --- |
| [`panel`](/api-docs/panel) | refuses; pages with `p_after` = `'<date>\|<id>\|<metric>\|<asset_class>'` |
| [`quote_history`](/api-docs/quotes) | refuses; pages with `p_after` = the last row's `trade_date` |
| [`fund_nav`](/api-docs/funds) | refuses; pages with `p_after` = the last row's `period` — **`p_entity_type` required to page** |
| [`option_history`](/api-docs/options) | refuses; no cursor — narrow `p_from`/`p_to` |
| [`termo_history`](/api-docs/termo) | refuses; no cursor — narrow `p_from`/`p_to` |
| [`financials`](/api-docs/financials) | refuses; no cursor — narrow the window or pin a statement |
| [`company_financials`](/api-docs/financials) | refuses; no cursor — narrow the window |
| [`anbima_classes`](/api-docs/anbima) | refuses; no cursor — narrow the window or pin a category |
| [`search_funds`](/api-docs/funds) | **25** rows anonymous, 200 signed in (`p_limit` clamped, not refused) |
| [`lookup`](/api-docs/lookup) | 20 rows |
| [`quote_latest`](/api-docs/quotes) | 1 row |
| [`coverage`](/api-docs/coverage) | one row per dataset, plus one `funds_<family>` row per family (~9) |
| [`metric_coverage`](/api-docs/coverage) | one row per filed `(family, metric)` pair |
| [`option_chain`](/api-docs/options) | **200** rows anonymous, 2,000 signed in (default 100) |
| [`option_exercises`](/api-docs/options) | **500** rows anonymous, 5,000 signed in (clamped) |
| [`panel` ids](/api-docs/panel) | **3 ids** anonymous / 50 signed in; universe mode signed in only |

#### The cursor protocol

| `p_after` | Meaning |
| --- | --- |
| absent / `null` | Whole result. **Refuses** above 1,000 rows. |
| `''` (empty string) | First page. |
| the key from the last row | The page after that key. |

A page shorter than 1,000 rows is the last. The key is `'<date>\|<id>\|<metric>\|<asset_class>'` for `panel`, and the bare date for `quote_history` and `fund_nav`.

- **`fund_nav` requires a family before it will page.** Its cursor is a bare period, unique only *within* a family — 385 CNPJs file under two in the same month. Without `p_after` you get every family at once, each row labelled with its `entity_type`.
- **`Range` paging does not work on RPC.** Rows 1000–1999 of an `/rpc/` call re-runs the function and returns the first page again. `p_after` is the RPC cursor; `Range` / `limit` / `offset` are the **view** cursor.

#### Reading `Content-Range`

On the GET views the header is the only truthful signal:

- `0-999/*` — you hit the platform cap; there is more you did not receive.
- `0-41/*` — you got everything.
- With `Prefer: count=exact` it becomes `0-999/1906`; the total after the slash is what you matched.

RPC functions raise `22023` instead, so a `Content-Range: 0-999/*` means you are on a **view**. The SDK reads the header and raises `SiloTruncated`.

#### Statement timeouts

**3 seconds for `anon`**, **8 seconds for `authenticated`**. Exceeding it fails with SQLSTATE `57014` and never returns a partial result — narrow the window, ids, or metrics. The first call after the database has been idle can be much slower than a warm one; retry once before concluding the API is down.

### Nulls and gaps

<Warning>
  Missing observations are **never** filled. No forward-fill, no interpolation, no last-observation-carried-forward, no synthesized month-end bar. Never a guessed price, NAV, fill, ranking, or identifier match.
</Warning>

Two distinct shapes:

- **An absent row.** In `panel`, a metric with no observation for that `(id, date)` produces no row — the fund and derived arms filter `value IS NOT NULL` before emitting.
- **A null column value.** In the views and series functions, a column the source did not publish comes back as JSON `null`. `panel`'s `close` and `volume` can too.

Specific guarantees:

- **`close_return` across a gap is null**, and therefore absent. Monthly, only when the previous row is the immediately preceding calendar month; daily, only when the previous session is within 7 calendar days. A **quotation-factor change also nulls the return** — a fatcot flip rescales the quote ±99.9% with no market move behind it.
- **Prices are unadjusted.** Every quote row carries `adjusted: false`. A 2:1 split reports roughly −50%. `close` is the price as published, which for a paper quoted per lot refers to 1,000 shares; `close_unit` divides by `quotation_factor` so levels compare across papers. Neither is corporate-action adjusted.
- **Not applicable is not missing.** `fund_nav` returns eleven columns for every family but each files only some. A null outside a family's list is set by construction; a null inside it is a blank in that filing. The map is `catalog().applicability`.
- **`delinquency` is a value, not a rate** — the delinquent portfolio in BRL. Ask for `nav` in the same call and divide in your notebook.
- **`freq=day` is quotes only.** No fund fundamental is daily. Mix asset classes at `freq=month`, where the equity value is the last real session of the month.
- **The `panel` grain is `(id, asset_class, date, metric)`** — four parts, not three. Pass `p_entity_type` or keep `asset_class` in your pivot key.
- **Identifier matches are never invented.** Company rows in `lookup` carry `tickers` from CVM's published FCA registry — a published mapping, not a name match.
- **Exercises and auctions are events, not quotes.** `option_exercises` (tpmerc 012/013) and the `auctions` view (017) carry one print per event. Never compute a return over either.

#### Regime breaks

Where a source format changed so one column means different things on either side of a date, the boundary is published, not smoothed — `catalog().regime_breaks` and that dataset's `coverage` row (`notes`). Read it before differencing anything.

<Warning>
  **FIDC `delinquency` starts at 2025-01.** CVM's pre-2025 monthly FIDC file carried no delinquency field, so `delinquency` is null on every `fidc` row through **2024-12-31** — not zero, not clean books. From **2025-01-31** it is filed on every row (a fund with none files `0`).

  Start the series at 2025-01. Never chain-link, difference or average across 2024-12 → 2025-01.
</Warning>

#### Default windows serve only complete periods

With no explicit `to`, fund metrics end at each family's latest COMPLETE period — a month CVM has only fractionally published is not served as if it were the industry, and FIP's early-filed year-end row waits for its year to close. An explicit `to` serves the window verbatim.

### Freshness

Call `coverage` before you claim anything is current. Four of its date columns mean four different things, and only two are freshness:

| Column | Means |
| --- | --- |
| `as_of` | The newest period that has landed **and has actually elapsed**. This is freshness. |
| `complete_through` | The newest period classified COMPLETE — what the default windows serve. |
| `newest_period` | The newest period **key** present. Can sit in the **future** (FIP is keyed 31-December). Never read as freshness. |
| `landed_at` | When ingest last **succeeded**. A later failed run never advances it. |

`metric_coverage` says which `(family, metric)` pairs are actually filed and over what span. **A pair absent from it is one the family never files** — not one whose data is late.

**Note**: do not confuse our health with the source's. `landed_at` says the pipeline ran and succeeded; `complete_through` says how much CVM has published. A stale `complete_through` with a fresh `landed_at` is Brazil's filing calendar, not an outage.

### Errors and empty results

PostgREST returns a JSON array on success. No envelope, no `count`, no `kind`.

| Status | Body | Meaning |
| --- | --- | --- |
| `200` | `[...]` | Rows. |
| `200` | `[]` | **Known query, no matching data.** Unknown ticker, unknown CNPJ, or a real ticker with no sessions in the window. |
| `400` | `42883` / `PGRST` codes | Malformed filter, bad argument type, out-of-range date. |
| `401` | `Invalid API key` / `Invalid JWT` | Missing or wrong `apikey`, or a publishable/secret key sent as `Authorization: Bearer`. |
| `404` | `PGRST202` | No function with that name **and argument set**. Check the `p_` names. |
| `400` | `22023` | **A ceiling, or a window over one page.** The message names the limit, what you sent, and how to get past it. |
| `401` | — | Landing tables are not reachable, by grant, for every caller. |
| `406` | — | You asked for a single object and the result had zero or more than one row. |
| `500` | `57014` | **Statement timeout**, not a server fault. |

An empty array carries no information about *why* it is empty. Confirm the identifier with [`lookup`](/api-docs/lookup) and the range with [`coverage`](/api-docs/coverage).

### What is live

SQL under `api` reaches production only when the analytical layer is applied — the nightly ingest, or an operator's `analytics-only` run — so a merge and a deploy are not the same moment. The truth is `POST /rpc/catalog`:

- `catalog().version` is the contract the database is actually serving. The SDK compares it for you and warns `SiloCatalogDrift`.
- `catalog().postgrest` lists the functions and views that exist on that server.

A documented function answering `404 PGRST202` has not been applied yet; it was not removed. The reverse also happens, so treat `catalog().postgrest` as a floor and a `200` as the last word.

### Caching

History whose end date is in the past is immutable — cache it aggressively (a day is reasonable). The latest session changes daily after the ingest cron; keep that short. `coverage` tells you when each dataset was last extended.

### Overview

Options are the same COTAHIST tape as [`quotes`](/api-docs/quotes) on a different market type: **`tpmerc` `070` = call, `080` = put**. They are roughly nine in ten rows of every session, which is why both endpoints here are narrower than their cash-market equivalents — neither will scan the whole segment.

Everything is unadjusted; every row carries `adjusted: false`.

Option rows carry **`underlying_ticker`**, and it is *published*, not the codneg-root convention: COTAHIST's ISIN on an option row is the **underlying's** ISIN, joined here to the same session's cash print. Measured on a full session, 14,895 of 14,900 rows matched 1:1 — PETR-prefix options split correctly between `PETR3` and `PETR4`, which a ticker root can never do. Null when the underlying had no cash print that day, never guessed.

Also on every row: `strike_points` (PTOEXE; null when not points-referenced), `strike_correction` (INDOPC) and `distribution_number` (DISMES — it changes on corporate events, a useful split signal). See the [COTAHIST dictionary](/api-docs/cotahist-dictionary).

**Note**: exercises are not quotes. `tpmerc` 012/013 rows are exercise *events* and live on `POST /rpc/option_exercises` (same required prefix, 500 rows anonymous / 5,000 signed in). Auction prints (`017`) live on `GET /auctions`. Computing returns over either is meaningless.

### `POST /rpc/option_chain`

One session's chain for a codneg prefix: every strike, expiry and side that printed.

```sql
api.option_chain(p_prefix      TEXT,
                 p_expiry_from DATE DEFAULT CURRENT_DATE,
                 p_trade_date  DATE DEFAULT NULL,
                 p_limit       INT  DEFAULT 100)
```

| Param | Meaning |
| --- | --- |
| `p_prefix` | Required, **at least 3 characters**. Upper-cased server-side. Matched as `codneg LIKE '<prefix>%'`. |
| `p_expiry_from` | Keep only series expiring on or after this date — by default, live contracts. Pass `null` to include expired series. |
| `p_trade_date` | Which session. Null means the latest session **in the option segment**, not the cash tape's latest. |
| `p_limit` | Clamped into `1..2000`; null means 100. The modest default is deliberate: `anon` has a 3-second timeout, and on the busiest chains a 200-row page already exceeds it and returns `57014`. |

<Warning>
  **A prefix is required, and a bad one is an error, not an empty array.** Fewer than 3 characters — including `null` or `""` — raises `22023` (HTTP 400). This is the only endpoint that refuses to run rather than returning `[]`: an unfiltered whole-market chain is tens of thousands of rows.
</Warning>

| Column | Type | Meaning |
| --- | --- | --- |
| `codneg` | text | The series' identifier. Pass it to `option_history` or [`panel`](/api-docs/panel). |
| `side` | text | `call` or `put`, derived **only** from `tpmerc`. Never inferred from the codneg's letter. |
| `strike` | numeric | Exercise price as published. |
| `expiry` | date | Expiration date. |
| `trade_date` | date | The session these prints are from. Constant across the response. |
| `open` / `high` / `low` / `close` | numeric | Session premiums. Unadjusted. |
| `trades` | integer | Number of trades. |
| `quantity` | numeric | Quantity traded, exactly as COTAHIST publishes it. |
| `volume` | numeric | Financial volume in BRL. |
| `isin` | text | ISIN as published. |
| `spec` | text | Paper specification (`especi`). |

Ordered by `expiry`, then `strike`, then side, then `codneg` — so an over-broad prefix that hits the clamp gives you whole near expiries rather than a random slice.

<CodeGroup>

```bash curl
curl -s -X POST "$SILO_URL/rpc/option_chain" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_prefix":"PETR","p_expiry_from":"2026-09-01"}'
```

```python Python

calls = [r for r in chain if r["side"] == "call"]
```

### `POST /rpc/option_history`

One series' daily prints over a window, ascending by `trade_date`.

```sql
api.option_history(p_codneg TEXT,
                   p_from   DATE DEFAULT CURRENT_DATE - 365,
                   p_to     DATE DEFAULT CURRENT_DATE)
```

`p_codneg` is the exact series code, e.g. `PETRH400`. Get one from `option_chain` — [`lookup`](/api-docs/lookup) does **not** resolve option codes and nothing enumerates them, so you need the underlying's root to find a series.

Returns [`quote_history`](/api-docs/quotes)'s column set with `side`, `strike` and `expiry` in place of `board` / `short_name`.

```bash
curl -s -X POST "$SILO_URL/rpc/option_history" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_codneg":"PETRH400","p_from":"2026-06-01","p_to":"2026-08-26"}'
```

**Note**: one 1,000-row page, and it refuses above it (`22023`) — never a truncated series. An option series lives for months, so you will not reach the page in practice. There is **no cursor**: narrow the window and call again.

### Prices are raw

Premiums are COTAHIST as published: no split, dividend or corporate-action adjustment anywhere in this warehouse.

`close_return` is deliberately **not offered for options**. In [`panel`](/api-docs/panel) it accepts `ticker` ids only, and even there it is computed from unadjusted closes. Options would inherit the same flaw with strike and quantity adjustments on top. Take `close` from `option_history` and difference it yourself, where you can see what you are assuming.

### Empty and error behavior

- **Unknown codneg → `200 []`.** Never a fabricated premium.
- **Known codneg, no sessions in the window** (before it listed, after it expired) → also `200 []`. Confirm the series with `option_chain` on a session you know it traded.
- **A prefix under 3 characters → `400`.** The one case where the API errors instead of returning an empty array.
- **`p_expiry_from` defaults to today**, so an `option_chain` call against a historical `p_trade_date` often comes back empty — those series have since expired. Pass `"p_expiry_from": null`.

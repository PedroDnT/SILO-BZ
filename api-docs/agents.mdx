### Overview

The operator guide for coding agents and the docs assistant. Agents should follow it in order.

It does not restate the contract. Row caps, tier ceilings, null semantics and regime breaks are written once on [Conventions & limits](/api-docs/conventions) and served as JSON by `POST /rpc/catalog`. What is here is the *procedure*.

### 2. Auth

The publishable key in [quickstart](/api-docs/quickstart) is shared, for testing. Anonymous access is free and deliberately small; signing in with GitHub raises four ceilings.

There is no `createApiKey`. `service_role` / Secret is never a caller credential. Do not mint or forge a key.

Sign in at [silo-bz-deloslabs.vercel.app/signin.html](https://silo-bz-deloslabs.vercel.app/signin.html). Send the token alongside the publishable key:

```bash
export SILO_URL="https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1"
export SILO_ANON_KEY="sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437"  # testing only

curl -s -X POST "$SILO_URL/rpc/panel" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Authorization: Bearer $SILO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"p_ids":["PETR4","VALE3","ITUB4","BOVA11"],"p_metrics":["close"]}'
```

The numbers live in the table on [Conventions & limits](/api-docs/conventions#authentication) and in `catalog().limits`. Read one of them — do not size a request from memory. Three things to carry anyway:

- **Rows per response never change with tier.**
- **Exceeding a ceiling is a `22023` error, never a silent trim.**
- **The token lasts about an hour and expiry is silent** — you drop back to anonymous, so a four-id call starts raising `22023`. Durable per-user keys do not exist yet.

Landing tables (`cvm_*`, `b3_cotahist`, `cia_*`, `bacen_*`) are closed to both tiers.

### 3. First live call is always `coverage`

```bash
curl -s -X POST "$SILO_URL/rpc/coverage" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Read `as_of` for freshness, `complete_through` for what the default windows serve, `notes` for a caveat the dates cannot carry. Column meanings: [Freshness](/api-docs/conventions#freshness).

A `401` is missing or wrong headers. An empty or error body is a failed fetch — **raise**, do not invent a last date.

### 4. Broad finance questions

*Does Brazilian equity stress show up in FIDC credit?*

1. `lookup` (`p_query`) / `search_funds` for FIDC CNPJs. Do not invent a ticker→fund join.
2. `panel` with `p_ids: ["PETR4", "<cnpj>", …]`, `p_metrics: ["close_return","delinquency","nav"]`, `p_freq: "month"`.
3. Pivot locally keeping `asset_class` in the key. Correlate pairwise-complete. **No ffill.**
4. `delinquency` is BRL outstanding, not a rate — divide by `nav`, which is why both are in the same call. For a FIDC the series **starts** at 2025-01 ([regime break](/api-docs/conventions#regime-breaks)).
5. Quotes are unadjusted. A missing month is not a two-month return.
6. Before reading a null as a gap, call `coverage` and `metric_coverage`.

There is no server-side `corr` — the catalog lists those as `notebook_reducers`. No RPC hands you a truncated result: functions page or refuse.

### 5. Screening a whole family

*Rank every FIDC by how much its delinquency worsened* is one paged `panel` call for a signed-in caller. Anonymous callers cannot use universe mode — enumerate from the `funds` **view** instead and batch ids within the ceiling.

<Steps>
  <Step title="Check the family is complete through your window">
    ```bash
    curl -s -X POST "$SILO_URL/rpc/coverage" -H "apikey: $SILO_ANON_KEY" \
      -H "Content-Type: application/json" -H "Content-Profile: api" -d '{}'
    ```
    Require `complete_through >= ` your end month on the `funds_fidc` row. Read `as_of`, not `newest_period`.
  </Step>
  <Step title="Enumerate the family from the funds view, paging">
    ```bash
    curl -s "$SILO_URL/funds?select=cnpj,fund_name,first_period,last_period\
&entity_type=eq.fidc&order=cnpj.asc&limit=1000&offset=0" \
      -H "apikey: $SILO_ANON_KEY" -H "Accept-Profile: api" -H "Prefer: count=exact"
    ```
    `Content-Range` carries the total. Keep only funds whose `first_period` / `last_period` span your window.
  </Step>
  <Step title="Signed in: walk the family with p_after">
    ```json
    {"p_ids": [], "p_metrics": ["delinquency", "nav"], "p_entity_type": "fidc",
     "p_from": "2025-09-01", "p_min_nav": 10000000, "p_min_months": 12, "p_after": ""}
    ```
    Next page: `p_after` = the last row's `"<date>|<id>|<metric>|<asset_class>"`. The SDK's `panel_all(...)` does the loop.
  </Step>
  <Step title="Keep asset_class in the key">
    The grain is `(id, asset_class, date, metric)`. A CNPJ that also files as an FI comes back twice per month.
  </Step>
  <Step title="Reduce locally">
    Compute `delinquency / nav` per fund-month (guard `nav` of zero), then rank on the change. Require a minimum of non-null months. No ffill.
  </Step>
</Steps>

Notebook [`04_fidc_credit`](https://github.com/PedroDnT/SILO-BZ/blob/main/notebooks/04_fidc_credit.ipynb) is this walkthrough as runnable code.

**Note**: a fund's **name** is never a taxonomy. For "FIDCs exposed to sector X" use `fidc_portfolio` (sector and SCR ladders), `fidc_cedentes` (named originators) or `fidc_sacados` (anonymized top-25 debtors) — see [FIDC concentration](/api-docs/fidc).

### 6. Integrity

<Warning>
  Never fabricate a price, NAV, fill, ranking, or ticker↔CNPJ match. Null stays null. Unknown id → no row. Known id, empty window → empty series, not a guessed last close.
</Warning>

Ingest (`run_daily`, landing tables) is out of scope for this API.

### Overview

`silo-client` is a small Python client for the Data API. One class, one method per endpoint, PostgREST underneath.

It exists to make the two things that bite hand-written callers impossible to miss: a **capped response raises** instead of returning a short series, and **views page while functions do not**.

It lives in the repository and is not on PyPI, deliberately, while the API's surface is still moving.

### Install

```bash
git clone https://github.com/PedroDnT/SILO-BZ && cd SILO-BZ
pip install -e sdk/              # httpx + pandas
```

Python ≥ 3.10. Or copy `sdk/silo_client/` into your project.

### Configure

```python
from silo_client import SiloClient

silo = SiloClient(url="https://zcjbtpxuhdekpwcxmepn.supabase.co",
                  key="sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437")   # testing key
```

Or set `SILO_URL` and `SILO_ANON_KEY` and call `SiloClient()`. To move to the signed-in tier, pass a user JWT as `token=` (or set `SILO_TOKEN`); `silo.tier` says which ceiling you are under.

### First calls

```python
silo.catalog()                    # metric map + constraints + limits — cached, call once
silo.coverage()                   # as_of (landed) vs complete_through (served), per dataset
silo.lookup("petrobras")          # company rows carry tickers=["PETR3","PETR4"]

df = silo.panel(["PETR4", "05754060000113"],
                metrics=["close_return", "delinquency"])   # wide DataFrame, (date) × (id, metric)
df.corr()                         # reductions happen HERE, not over HTTP
```

`panel` validates metric names against the live catalog, so a typo raises `ValueError` client-side instead of returning an empty panel. Missing observations stay `NaN` — never filled.

### Every method

One per published endpoint. Dates accept `date` objects or ISO strings; `None` means the server's default, which for fund windows is the honest one.

### The three rules the client enforces

#### A capped response raises

PostgREST stops every response at 1,000 rows and answers `200` with the oldest page. The client asks for a true count (`Prefer: count=exact`) and raises rather than hand you the short answer:

```python
from silo_client import SiloTruncated

try:
    rows = silo.quote_history("PETR4", start="2019-01-01")
except SiloTruncated as e:
    print(e.returned, "of", e.total)      # 1000 of 4382
    print(e.rows[-1]["trade_date"])       # where the cut fell — inspect, never use
```

For the three long series the server refuses instead (`SiloOverCap`), and each pages with its own cursor:

```python
from silo_client import SiloOverCap

try:
    df = silo.panel(["PETR4"], ["close"], start="2019-01-01", freq="day")
except SiloOverCap:
    rows = silo.panel_all(["PETR4"], ["close"], start="2019-01-01", freq="day")

quotes = silo.quote_history_all("PETR4", start="2019-01-01")

# nav pages within ONE family — the cursor is a bare period, and 385 CNPJs
# file under two in the same month, so the family is not optional
nav = silo.fund_nav_all("05754060000113", "fi", start="2019-01-01")

# a whole family, signed in: every FIDC with >= 12 filed months and >= R$10mm
fidcs = silo.panel_all(None, ["delinquency", "nav"], entity_type="fidc",
                       min_nav=1e7, min_months=12, wide=True)
```

For `option_history`, `termo_history`, `financials`, `company_financials` and `anbima_classes` there is no cursor: `SiloOverCap` means narrow the window.

`panel(wide=True)` refuses to pivot a CNPJ that files under two families in the same month — pass `entity_type=`, or take `wide=False` and keep `asset_class` in your own key.

#### Views page; functions do not

```python
page2 = silo.view("funds", order="cnpj.asc", limit=1000, offset=1000)   # one explicit page
fidcs = silo.view_all("funds", entity_type="eq.fidc", order="cnpj.asc",
                      select="cnpj,fund_name,first_period,last_period")  # every page
```

`view_all` / `iter_view` **require an `order`** — offset paging without a total order can duplicate a row at one boundary and drop one at the next. A `view()` with no `limit` that lands on the cap still raises: that is the silent cut, not a page.

#### The client tells you when it is out of date

`catalog()` compares the server's catalog version against the one the client was written for and warns `SiloCatalogDrift` on a mismatch. It never refuses — everything read off the catalog keeps working. `silo.limits()` is the tier table straight from the server.

### Errors

| Exception | When |
| --- | --- |
| `SiloError` | any 4xx/5xx — carries `.status` and the server's own message |
| `SiloTruncated` | a capped response (views, series functions); `.returned`, `.total`, `.rows` |
| `SiloOverCap` | a window over one page (`22023`); page with the cursor or narrow |
| `SiloTimeout` | SQLSTATE `57014` — the tier's statement budget (3s / 8s) |
| `ValueError` | caught before the round trip: unknown metric, missing `order`, both/neither of an exactly-one pair |

The client never retries a 4xx into a different answer, and connection retries are safe only because every endpoint is read-only.

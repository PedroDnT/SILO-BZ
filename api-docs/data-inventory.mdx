### 2. What we could ingest and don't

Each line is a decision, not an oversight; measurements are in the [repository inventory](https://github.com/PedroDnT/SILO-BZ/blob/main/docs/DATA_INVENTORY.md) §2.

#### Other gaps

| Gap | Why |
| --- | --- |
| FIDC informe tabs unread | Ten of the ZIP's 18 members are ingested. Unread: tab I's other ~70 columns (asset composition, admin, condomínio), `III` (2025+), `V` (maturity ladder), `VII` (custody split, repurchases), `IX` (assignment prices), `X_1` / `X_1_1` (quotaholders per tranche and by investor type), `X_5` (liquidity ladder), `X_7` (collateral coverage) |
| Historical B3 index composition | Point-in-time membership and weights beyond the current portfolio in `b3_index_portfolio`. Gate: verify the archive, effective dates and each CIND layout version |
| FIDC tranche / flows / aging before 2025 | CVM publishes **no HIST equivalent** for tabs X2/X4/VI: an upstream limit, not a backlog item |
| FIAGRO before 2025-05 | the monthly file itself begins there |
| CIA ITR/DFP 2010–2018 | pipeline is wired from 2019; partitions are declared and empty |
| `cvm_fi_diario` before 2019 | RANGE partitions floor at 2019-01-01. Adding CVM's HIST back to 2000 means ~a decade of daily rows on the largest table. Deliberate |
| Company ↔ fund ownership beyond CDA | Two published edges exist and neither is inferred: `cvm_fi_cda_acoes.cd_ativo` (B3 ticker, joined to `cia_ticker`) and `cvm_fi_cda_debentures.cpf_cnpj_emissor` (joins to `cia_*` directly). No name matching, ever |
| Anything needing a licence or login | `etf_market_snapshot` is the one scrape, and it self-skips without its token |

#### Known defects in what is ingested

Both are written up with measurements in the repository inventory.

- **`cvm_fi_cda` keeps one bond in five and calls it the class total.** BLC_1 is one row per security, but the shipped key carries none of `CD_SELIC` / `CD_ISIN` / `DT_VENC`, so 80.4% of rows are lost on upsert. The fix is additive: a `cvm_fi_cda_titpub` table keyed on the security, leaving `cvm_fi_cda` as the class roll-up the dashboards read.
- **`cia_event` cannot key an IPE filing with no protocol, and before 2015 none have one.** The natural key is `(protocolo, versao)`, so those rows are dropped, not given a synthesized key. 2010–2014 cannot be loaded; 2015 silently loses 12% of its filings. The fix is a second key era (a `row_hash` for protocol-less rows), which changes the grain and waits for the owner's call.

### 4. How it is served

Five objects do the work; everything else is a typed view over `b3_cotahist`.

| Object | Does |
| --- | --- |
| `coverage()` | what is here, and how complete (read this FIRST) |
| `lookup()` | a name/ISIN/CNPJ/ticker to an id you can query |
| `panel()` | `(id, date, metric, value)`, mixing tickers and fund CNPJs |
| `quote_*()` | one instrument's own series |
| `fund_*()` | one fund's own series |

`panel` is the primitive: correlation, ranking and spreads are reductions of it, done in the client.

| Family | Native grain | Served as | Consequence |
| --- | --- | --- | --- |
| B3 cash | **session** | day, or month = last session | a monthly close is a real print, never an average |
| FI | fund × day (`cvm_fi_diario`) | **month** | daily rows exist but the panel does not serve them for funds |
| FIDC | fund × month-end | month | `delinquency` is a **BRL value**, not a rate: divide by `nav` yourself |
| FII | fund × month | month | the only family carrying `yield` |
| FIAGRO | fund × month | month | begins 2025-05: a shorter axis, not a thinner one |
| FIP | fund × **filing date** × share class | month | files 3–4× a year, not annually |
| CIA | company × filing × account line | **not served** by `panel` | a statement line fits no fund-shaped endpoint |

### Notes

- **FIP reads as annual and is not:** a fund files quarterly or three times a year, one row per share class each time. Until 2026-08-31 the key discarded 72–77% of every published file on upsert. The key is now `(cnpj, doc_type, period, classe_cota, row_hash)`.
- **No fabricated observations.** A missing month is absent, never interpolated or carried forward.
- **`as_of` ≠ `complete_through`.** The first is the newest row held, the second the last period believed complete. `coverage()` returns both.
- **Prices are unadjusted.** A split reads as a real ~50% jump; `adjusted` is `false` on every row. Exceptions: `quote_history`'s `close_adj`, continuous across splits and refused where unproven, and the selectable `close_total_return`, NULL with a reason where unproven.
- **1,000 rows per response, for everyone.** Signing in raises ids, page sizes and the query budget, never this.
- `coverage()` has no row for `fund_holdings` or `fund_debentures` yet; take freshness from the rows (`ORDER BY period DESC LIMIT 1`).
- Keeping this honest: a new dataset is a row in §1; a decision against one is a row in §2 with the reason; ingested but unserved belongs in §3. A table in none of the three is what this page exists to prevent.

### Overview

`company_events` serves CVM's IPE feed (Informações Periódicas e Eventuais) for one
listed company, newest delivery first: material facts (_Fato Relevante_), market
notices, assembly calls and minutes, and the rest of what companies file outside
the ITR/DFP statements.

```bash
curl -s -X POST "$SILO_URL/rpc/company_events" \
  -H "apikey: $SILO_ANON_KEY" -H "Content-Type: application/json" \
  -d '{"p_id":"PETR4","p_category":"Fato Relevante"}'
```

```python
silo.company_events("PETR4", category="Fato Relevante")
```

### The company is resolved exactly as `financials` resolves it

`p_id` takes a B3 ticker, a 14-digit CNPJ or a CVM code. A ticker resolves **only**
through CVM's published FCA map (active listings), so `PETR4`, `33000167000101`
and `9512` are the same company, a delisted code resolves to nothing, and nothing
is ever matched by name. An id that resolves to nothing returns an empty array, as
for [`financials`](/api-docs/financials). Find ids with [`lookup`](/api-docs/lookup).

### One row per protocol, as filed

- CVM re-files an IPE document under the same protocol with a higher version.
  Each protocol is served **once, at its newest version**; `version` says which.
- `category`, `event_type`, `species` and `subject` are CVM's text exactly as
  filed — Portuguese, never translated or normalised. `p_category` matches the
  label exactly (`Fato Relevante`, `Comunicado ao Mercado`, …); an unknown one
  raises `22023` listing the categories held.
- `source_url` is the document's link on CVM's RAD. Open it; Silo stores the
  metadata, not the document.
- `delivery_date` is `Data_Entrega` (CVM prints a date, no time) and the window
  runs on it — on `reference_date` for a row published without one. Default: the
  12 months before `p_to` or today.

### Where the history stops

CVM assigned **no protocol number** to IPE filings before 2015, and still omits
it on a minority of filings (12% of 2015). Silo's key for these rows is
(protocol, version), and a key is never synthesized, so **those filings are not
held**. History therefore starts in 2015 and no year is complete. An empty window
before 2015, or a filing you know exists and cannot find, is that limit — not a
quiet company. [`coverage()`](/api-docs/coverage) carries the same note on its
`company_events` row.

### Recuperação judicial documents

`rj_listed_documents(p_id, p_from, p_to, p_doc_type)` returns the recuperação judicial and extrajudicial documents that listed companies filed with CVM IPE. It reads the same filings as `company_events`, with one row per `protocolo` at its newest `versao`.

- `signal` says why a row is here. `categoria` is CVM's own category for companies in recuperação judicial or extrajudicial. `fato_relevante` is a Fato Relevante whose subject names such a recovery. The category alone missed 49 such Fatos Relevantes in 2026.
- `cadastro_status` and `cadastro_status_since` are the company register's status as filed. The register lags the filings, so it is a second signal only.
- `p_id` NULL means every company; otherwise it is resolved by identifier, never by name. The window is the delivery date. An unknown `p_doc_type` raises `22023` and lists the types held.
- It refuses above one 1,000-row page (`22023`).

### Limits

Raise-only above one 1,000-row page (`22023`, [Row caps](/api-docs/conventions#row-caps)):
narrow the window or pin `p_category`. A large issuer files a few hundred
documents a year, so a year fits.

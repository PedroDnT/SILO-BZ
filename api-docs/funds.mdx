### Overview

Brazilian investment vehicles as disclosed to the CVM, keyed by **CNPJ**.

| `entity_type` | Vehicle |
| --- | --- |
| `fi` | Fundos de Investimento (open-ended funds) |
| `fidc` | Fundos de Investimento em Direitos Creditórios (receivables) |
| `fii` | Fundos de Investimento Imobiliário (real estate) |
| `fip` | Fundos de Investimento em Participações (private equity) |
| `fiagro` | Fundos de Investimento nas Cadeias Produtivas Agroindustriais |

CNPJ input is stripped to its 14 digits, so `12.345.678/0001-90` and `12345678000190` are the same argument.

**Note**: ETFs are carved out of this universe and are not in `api.funds`. Post-CVM-175 share classes make their NAV series structurally different, so they are served separately.

### `GET /funds`

The registry view: one row per `(cnpj, entity_type)` — what we hold, not what the fund is worth.

Query params: `cnpj=eq.<digits>` (the view does no normalization), `entity_type`, `select`, `limit`. The view has no built-in cap — always set one.

| Column | Type | Meaning |
| --- | --- | --- |
| `cnpj` | text | 14-digit CNPJ, unpunctuated. The natural key. |
| `entity_type` | text | `fi` \| `fidc` \| `fii` \| `fip` \| `fiagro`. |
| `fund_name` | text | Registered name. Nullable — the registry feed does not cover every CNPJ that appears in periodic filings. |
| `status` | text | Registry status as published. Nullable, same reason. |
| `fund_class` | text | The registry's `tp_fundo`, as published. Nullable. |
| `first_period` | date | Earliest period held. |
| `last_period` | date | Latest period held. `fip` periods are yearly, mapped to Jan 1 / Dec 31. |
| `n_reports` | bigint | Count of distinct periods held. Coverage, not a quality score. |

<CodeGroup>

```bash curl
curl -s -G "$SILO_URL/funds" \
  -H "apikey: $SILO_ANON_KEY" \
  --data-urlencode "select=cnpj,fund_name,entity_type,first_period,last_period,n_reports" \
  --data-urlencode "entity_type=eq.fidc" \
  --data-urlencode "order=n_reports.desc" \
  --data-urlencode "limit=3"
```

```python Python
params = {
    "select": "cnpj,fund_name,entity_type,first_period,last_period,n_reports",
    "entity_type": "eq.fidc",
    "order": "n_reports.desc",
    "limit": 3,
}
rows = requests.get(f"{URL}/funds", headers=H, params=params).json()
```

```javascript JavaScript
const { data } = await supabase
  .from('funds')
  .select('cnpj, fund_name, entity_type, first_period, last_period, n_reports')
  .eq('entity_type', 'fidc')
  .order('n_reports', { ascending: false })
  .limit(3)
```

</CodeGroup>

### `POST /rpc/search_funds`

Substring search over the registry, ordered by `latest_aum` descending, nulls last.

```sql
api.search_funds(p_query       TEXT DEFAULT '',
                 p_entity_type TEXT DEFAULT NULL,
                 p_limit       INT  DEFAULT 50)
```

| Param | Meaning |
| --- | --- |
| `p_query` | Case-insensitive substring, matched against **either the CNPJ or the fund name**. Default `''` matches everything. A fund with a null `fund_name` can only be found by CNPJ. |
| `p_entity_type` | Restrict to one type. Null means all. |
| `p_limit` | Clamped by tier: **25** anonymous, 200 signed in. A larger value is silently reduced, not refused. |

Returns `cnpj`, `entity_type`, `fund_name`, `first_period`, `last_period`, and `latest_aum` — the most recent non-null net assets, nullable, sorting last rather than being zero-filled.

```bash
curl -s -X POST "$SILO_URL/rpc/search_funds" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_query":"multisetorial","p_entity_type":"fidc","p_limit":10}'
```

### `POST /rpc/fund_profile`

One fund's summary card: coverage plus peak and latest AUM.

```sql
api.fund_profile(p_cnpj TEXT)
```

| Column | Type | Meaning |
| --- | --- | --- |
| `cnpj`, `entity_type`, `fund_name`, `status` | text | As in the registry view. |
| `first_period` / `last_period` | date | Earliest and latest period held. |
| `n_months_reported` | bigint | Distinct periods held — the view's `n_reports`. |
| `peak_aum` | numeric | Maximum net assets ever reported. |
| `latest_aum` | numeric | Net assets at the most recent non-null period. |
| `is_active` | boolean | `last_period >= CURRENT_DATE - 90 days`. A **filing-recency** flag, not a legal status — CVM publishes on a 1–2 month lag. |

```bash
curl -s -X POST "$SILO_URL/rpc/fund_profile" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_cnpj":"12.345.678/0001-90"}'
```

**Note**: a CNPJ in the registry with no monthly fundamentals returns `[]` — the profile is built from the monthly facts. A CNPJ filing under more than one `entity_type` returns one row per type; do not assume a single row.

### `POST /rpc/fund_nav`

The monthly fundamentals series for one CNPJ — the fund-side equivalent of `quote_history`.

```sql
api.fund_nav(p_cnpj        TEXT,
             p_from        DATE DEFAULT '2019-01-01',
             p_to          DATE DEFAULT CURRENT_DATE,
             p_entity_type TEXT DEFAULT NULL)
```

`p_from`'s default is a **fixed date**, not a rolling window — omit it for the full stored history. `p_entity_type` is needed only for the rare CNPJ that reports under two.

| Column | Type | Meaning |
| --- | --- | --- |
| `cnpj` | text | 14-digit CNPJ. |
| `period` | date | The filing period **as stored, per family** (see below). `date_trunc('month', period)` before aligning families. |
| `entity_type` | text | Vehicle type for this row. |
| `nav` | numeric | Net assets (`vl_patrim_liq`). The headline size figure. |
| `quota` | numeric | Unit quota value (`vl_quota`). **`fi` only.** |
| `quotaholders` | integer | Unit-holders (`nr_cotst`). **`fi` and `fii` only.** |
| `delinquency` | numeric | Delinquent portfolio **value** (`vl_inadimpl`) in BRL — **`fidc` and `fiagro` only**. An amount, not a rate. |
| `monthly_yield` | numeric | Monthly yield percentage (`pct_yield_mes`). **`fii` only.** |
| `inflows` / `redemptions` | numeric | Gross monthly subscriptions / redemptions. **`fi` only.** |
| `assets` | numeric | Total assets (`vl_ativo`), distinct from net assets. **`fii` only.** |

Ordered by `period`, then `entity_type`.

#### Which columns each family files

Every family returns the same eleven columns; each fills only some. Outside a family's list a null is *not applicable* and carries no information; inside it, it is a blank in that month's filing. Machine-readable as `catalog().applicability.fund_nav.columns_by_family`.

| Family | `nav` | `quota` | `quotaholders` | `delinquency` | `monthly_yield` | `inflows` | `redemptions` | `assets` | `period` is |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `fi` | ✓ | ✓ | ✓ | — | — | ✓ | ✓ | — | first of month |
| `fidc` | ✓ | — | — | ✓ (2025-01+) | — | — | — | — | **month-end** |
| `fiagro` | ✓ | — | — | ✓ | — | — | — | — | first of month |
| `fii` | ✓ | — | ✓ | — | ✓ | — | — | ✓ | first of month |
| `fip` | ✓ | — | — | — | — | — | — | — | 31-Dec, yearly |

<Warning>
  **FIDC `delinquency` starts in 2025-01 — a regime break, not a series.** Every `fidc` row through `2024-12-31` has `delinquency: null` — not zero, not clean books. From `2025-01-31` it is filed on every row (a fund with none files `0`). Never chain-link, difference or average across the boundary; start at 2025-01. Published in `catalog().regime_breaks` and on the `funds_fidc` [`coverage`](/api-docs/coverage) row.
</Warning>

```bash
curl -s -X POST "$SILO_URL/rpc/fund_nav" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_cnpj":"12345678000190","p_from":"2024-01-01","p_to":"2026-06-30"}'
```

```json
[
  {
    "cnpj": "12345678000190", "period": "2025-03-31", "entity_type": "fidc",
    "nav": 388120044.12, "quota": null, "quotaholders": null,
    "delinquency": 9120044.7, "monthly_yield": null,
    "inflows": null, "redemptions": null, "assets": null
  }
]
```

#### Notes

- **Nulls here are real.** A column is null because the family does not file it, or because the filing left it blank — never because a value was dropped. Nothing is forward-filled; a month with no filing is an **absent row**. Check `period` continuity before differencing.
- **One 1,000-row page, and it refuses above it** (`22023`). At a monthly grain 1,000 rows is over 80 years of one fund, so reaching it usually means the request is wrong.
- **Paging requires `p_entity_type`.** The cursor is a bare `period`, unique only within a family — 385 CNPJs file under two in the same month. Drop `p_after` to get the whole result with every row labelled.

  ```json
  { "p_cnpj": "05754060000113", "p_entity_type": "fi", "p_after": "" }
  { "p_cnpj": "05754060000113", "p_entity_type": "fi", "p_after": "2023-06-30" }
  ```

  In the SDK: `silo.iter_fund_nav("05754060000113", "fi")`.
- **`period` and `period_month` are two conventions for the same month.** `period` is CVM's filed month-end date; `period_month` is the first of that month, which is how [`panel`](/api-docs/panel) keys fund observations. Join a nav series to a panel on `period_month`.
- **Empty results**: unknown CNPJ, or a real CNPJ with no filings in the window → `200 []`. A CNPJ that exists only as an ETF is absent by design. Passing `"p_from": null` explicitly returns `[]` — omit the key for the default.

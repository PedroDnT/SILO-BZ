B3 COTAHIST cash-market prints (`tpmerc = 010`), exactly as published. Nothing here is
split- or dividend-adjusted, and every row says so with `adjusted: false`. `asset_class`
is derived conservatively from B3's published `tpmerc` and `especi`: `equity`, `unit`,
`bdr`, `fund_quota`, `index`, `right`, `bonus`, or `cash_security`. To split `fund_quota` into ETF vs FII vs
FIAGRO, use [`fund_quotas`](/api-docs/instruments)' `fund_type` column — it comes from
B3's published CODBDI board code (see the [COTAHIST
dictionary](/api-docs/cotahist-dictionary)).

<Warning>
  **`close` is the price of `quotation_factor` units, not always one.** The API now
  serves that division for you as **`close_unit`** = `close / quotation_factor`, so
  price levels are comparable across papers without any arithmetic on your side. The
  factor is 1 for almost everything (13 tickers on the whole 2019–2026 tape carry
  another value), but a paper quoted per lot reads 1000× its unit price in `close`.
  `close_return` is still computed on raw `close` and is null across a factor change.
</Warning>

<Warning>
  **Nothing here is corporate-action adjusted.** `close_unit` divides by a published
  field; it does not account for splits, groupings or bonuses, and `adjusted` is
  `false` on every row. A split still appears as a jump in the price series.
</Warning>

The grain is **`(ticker, trade_date, board, term_days)`**. A single ticker can print on more
than one board on the same day, so a query that does not pin `board` can return several rows
per session. COTAHIST `codbdi` varies by instrument type (for example `02` for common
equities, `12` for FIIs, `14` for ETFs, and `34` for BDRs). The functions automatically
select the ticker's latest board unless you pass one explicitly.

## `GET /quotes`

The view. Full column set, arbitrary filters, arbitrary sort — use it when you want
cross-sectional slices (a whole session, a set of tickers) rather than one instrument's
series.

<ParamField query="ticker" type="string">
  Filter by ticker, e.g. `ticker=eq.PETR4`. Stored upper-case; the view does **not**
  normalize your input, so send it upper-case (unlike the functions, which upper-case for you).
</ParamField>

<ParamField query="trade_date" type="date">
  Session date, e.g. `trade_date=gte.2026-01-01`.
</ParamField>

<ParamField query="board" type="string">
  COTAHIST `codbdi`. Do not assume `02` outside ordinary equities.
</ParamField>

<ParamField query="select" type="string">
  Columns to project. Omit for all of them.
</ParamField>

<ParamField query="order" type="string">
  e.g. `order=trade_date.desc`.
</ParamField>

<ParamField query="limit" type="integer">
  Page size. The view itself has no built-in cap — always set one.
</ParamField>

### Columns

<ResponseField name="ticker" type="text">
  B3 negotiation code (`codneg`). Part of the grain.
</ResponseField>
<ResponseField name="trade_date" type="date">
  Session date. Part of the grain.
</ResponseField>
<ResponseField name="board" type="text">
  BDI code / `codbdi`; its meaning varies by instrument type. Part of the grain.
</ResponseField>
<ResponseField name="term_days" type="text">
  COTAHIST `prazot`. A **text** field despite the name, usually empty for cash. Part of the
  grain. Only on the view — the functions do not return it.
</ResponseField>
<ResponseField name="short_name" type="text">
  Issuer short name (`nome_resumido`).
</ResponseField>
<ResponseField name="spec" type="text">
  Paper specification (`especi`), e.g. the share class.
</ResponseField>
<ResponseField name="currency" type="text">
  Currency, defaulting to `R$` when the source leaves it blank.
</ResponseField>
<ResponseField name="open" type="numeric">
  Opening price.
</ResponseField>
<ResponseField name="high" type="numeric">
  Session high.
</ResponseField>
<ResponseField name="low" type="numeric">
  Session low.
</ResponseField>
<ResponseField name="average" type="numeric">
  Session average price.
</ResponseField>
<ResponseField name="close" type="numeric">
  Closing price. Unadjusted.
</ResponseField>
<ResponseField name="bid" type="numeric">
  Best bid at close (`oferta_compra`).
</ResponseField>
<ResponseField name="ask" type="numeric">
  Best ask at close (`oferta_venda`).
</ResponseField>
<ResponseField name="trades" type="integer">
  Number of trades (`negocios`).
</ResponseField>
<ResponseField name="quantity" type="numeric">
  Shares traded (`quantidade`).
</ResponseField>
<ResponseField name="volume" type="numeric">
  Financial volume in BRL.
</ResponseField>
<ResponseField name="isin" type="text">
  ISIN as published.
</ResponseField>
<ResponseField name="quotation_factor" type="integer">
  COTAHIST `fator_cotacao` — the number of shares the quoted price refers to.
</ResponseField>
<ResponseField name="close_unit" type="number">
  Close per single quoted unit: `close / quotation_factor`, both published. Division by
  a published field, not an adjustment — see the warning above.
</ResponseField>
<ResponseField name="adjusted" type="boolean">
  Always `false`. Constant, so nobody mistakes these for adjusted prices.
</ResponseField>
<ResponseField name="source" type="text">
  Provenance, `b3_cotahist`.
</ResponseField>
<ResponseField name="fetched_at" type="timestamptz">
  When the pipeline ingested this row. Only on the view.
</ResponseField>
<ResponseField name="asset_class" type="text">
  Conservative B3 type: `equity`, `unit`, `bdr`, `fund_quota`, `index`, `right`,
  `bonus`, or `cash_security`. `index` is an index line (IBOV11 — not an ETF,
  whatever the ticker suggests); `right` and `bonus` are claims, not the
  security itself; `cash_security` is the residual.
</ResponseField>

### Example

<CodeGroup>

```bash curl
curl -s -G "$SILO_URL/quotes" \
  -H "apikey: $SILO_ANON_KEY" \
  --data-urlencode "select=ticker,trade_date,board,close,volume,adjusted,asset_class" \
  --data-urlencode "ticker=in.(PETR4,VALE3)" \
  --data-urlencode "board=eq.02" \
  --data-urlencode "trade_date=eq.2026-08-26"
```

```python Python
params = {
    "select": "ticker,trade_date,board,close,volume,adjusted,asset_class",
    "ticker": "in.(PETR4,VALE3)",
    "board": "eq.02",
    "trade_date": "eq.2026-08-26",
}
rows = requests.get(f"{URL}/quotes", headers=H, params=params).json()
```

```javascript JavaScript
const { data } = await supabase
  .from('quotes')
  .select('ticker, trade_date, board, close, volume, adjusted, asset_class')
  .in('ticker', ['PETR4', 'VALE3'])
  .eq('board', '02')
  .eq('trade_date', '2026-08-26')
```

</CodeGroup>

```json
[
  { "ticker": "PETR4", "trade_date": "2026-08-26", "board": "02",
    "close": 41.2, "volume": 1204533210.0, "adjusted": false, "asset_class": "equity" },
  { "ticker": "VALE3", "trade_date": "2026-08-26", "board": "02",
    "close": 58.94, "volume": 987441002.5, "adjusted": false, "asset_class": "equity" }
]
```

## `POST /rpc/quote_history`

One ticker's daily series over a window. Ordered by `trade_date` ascending.

```sql
api.quote_history(p_ticker TEXT,
                  p_from   DATE DEFAULT CURRENT_DATE - 365,
                  p_to     DATE DEFAULT CURRENT_DATE,
                  p_board  TEXT DEFAULT NULL)
```

<ParamField body="p_ticker" type="string" required>
  Ticker. Upper-cased and trimmed server-side, so `petr4` is fine.
</ParamField>

<ParamField body="p_from" type="date" default="CURRENT_DATE - 365">
  Window start, inclusive.
</ParamField>

<ParamField body="p_to" type="date" default="CURRENT_DATE">
  Window end, inclusive.
</ParamField>

<ParamField body="p_board" type="string" default="null">
  Board filter. Null or omitted automatically selects the board on the ticker's latest
  stored row. Pass a code explicitly only when you need that exact BDI category.
</ParamField>

Returns the view's columns minus `term_days` and `fetched_at`: `ticker`, `trade_date`,
`board`, `short_name`, `spec`, `currency`, `open`, `high`, `low`, `average`, `close`, `bid`,
`ask`, `trades`, `quantity`, `volume`, `isin`, `quotation_factor`, `adjusted`, `source`,
`asset_class`, `close_unit`.

<CodeGroup>

```bash curl
curl -s -X POST "$SILO_URL/rpc/quote_history" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_ticker":"PETR4","p_from":"2026-01-02","p_to":"2026-08-26"}'
```

```python Python
body = {"p_ticker": "PETR4", "p_from": "2026-01-02", "p_to": "2026-08-26"}
rows = requests.post(f"{URL}/rpc/quote_history", headers=H, json=body).json()
```

```javascript JavaScript
const { data } = await supabase.rpc('quote_history', {
  p_ticker: 'PETR4',
  p_from: '2026-01-02',
  p_to: '2026-08-26',
})
```

</CodeGroup>

```json

  {

    "short_name": "PETROBRAS",

    "open": 38.4,
    "high": 38.95,
```

<Warning>
  **Capped at 5,001 rows.** 5,000 daily prints is roughly twenty years of one ticker's
  sessions, so this is a backstop rather than a normal limit. If you get exactly 5,001 rows,
  the oldest sessions were kept and the newest were cut — narrow `p_from` / `p_to` and call
  again rather than using the truncated series.
</Warning>

## `POST /rpc/quote_latest`

The most recent stored session for one ticker. At most one row.

```sql
api.quote_latest(p_ticker TEXT,
                 p_board  TEXT DEFAULT NULL)
```

<ParamField body="p_ticker" type="string" required>
  Ticker. Upper-cased and trimmed server-side.
</ParamField>

<ParamField body="p_board" type="string" default="null">
  Board filter; `null` means "latest across all boards".
</ParamField>

Same columns as `quote_history`.

<CodeGroup>

```bash curl
curl -s -X POST "$SILO_URL/rpc/quote_latest" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_ticker":"PETR4"}'
```

```python Python
rows = requests.post(
    f"{URL}/rpc/quote_latest", headers=H, json={"p_ticker": "PETR4"}
).json()
latest = rows[0] if rows else None      # empty list = we have no print
```

```javascript JavaScript
const { data } = await supabase.rpc('quote_latest', { p_ticker: 'PETR4' })
const latest = data?.[0] ?? null
```

</CodeGroup>

<Warning>
  **"Latest" means the latest session we have stored, not today.** It is whatever the last
  successful COTAHIST ingest loaded — check `trade_date` on the row, and
  [`coverage`](/api-docs/coverage) for the dataset as a whole. The API will never advance a
  stale close to today's date to make it look current.
</Warning>

## Empty and error behavior

- **Unknown ticker → `200 []`.** Not a 404, and never a fabricated last close. An empty
  array means "no row matches", full stop.
- **Known ticker, no sessions in the window** (a holiday range, or a window before the
  paper listed) → also `200 []`. The two cases are indistinguishable from the response
  alone; use [`lookup`](/api-docs/lookup) to confirm the ticker exists.
- **Wrong board** is a common cause of a surprising empty result. Some papers do not print
  on `02`; retry with `"p_board": null`.
- A malformed date or filter returns `400`.

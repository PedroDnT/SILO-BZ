### Overview

B3 COTAHIST cash-market prints (`tpmerc = 010`), exactly as published. Nothing is split- or dividend-adjusted, and every row carries `adjusted: false`.

The grain is **`(ticker, trade_date, board, term_days)`**. A ticker can print on more than one board on the same day, so a query that does not pin `board` can return several rows per session. `codbdi` varies by instrument type (`02` common equities, `12` FIIs, `14` ETFs, `34` BDRs). The functions select the ticker's latest board unless you pass one.

`asset_class` is derived conservatively from `tpmerc` and `especi`. To split `fund_quota` into ETF vs FII vs FIAGRO use [`fund_quotas`](/api-docs/instruments)' `fund_type`.

<Warning>
  **`close` is the price of `quotation_factor` units, not always one.** `close_unit` = `close / quotation_factor` is served for you. The factor is 1 for almost everything (13 tickers on the whole 2019–2026 tape carry another value), but a paper quoted per lot reads 1000× its unit price in `close`.

  **Neither is corporate-action adjusted.** `close_unit` divides by a published field; it does not account for splits, groupings or bonuses. A split still appears as a jump. `close_return` is computed on raw `close` and is null across a factor change.
</Warning>

### `GET /quotes`

The view — full column set, arbitrary filters and sort. Use it for cross-sectional slices (a whole session, a set of tickers) rather than one instrument's series.

Query params: `ticker` (stored upper-case; the view does **not** normalize your input, unlike the functions), `trade_date`, `board`, `select`, `order`, `limit`. The view has no built-in cap — always set one.

| Column | Type | Meaning |
| --- | --- | --- |
| `ticker` | text | B3 negotiation code (`codneg`). Part of the grain. |
| `trade_date` | date | Session date. Part of the grain. |
| `board` | text | BDI code / `codbdi`; meaning varies by instrument type. Part of the grain. |
| `term_days` | text | COTAHIST `prazot`. **Text** despite the name, usually empty for cash. Part of the grain. View only. |
| `short_name` | text | Issuer short name (`nome_resumido`). |
| `spec` | text | Paper specification (`especi`), e.g. the share class. |
| `currency` | text | Defaults to `R$` when the source leaves it blank. |
| `open` / `high` / `low` / `average` / `close` | numeric | Session prices. Unadjusted. |
| `bid` / `ask` | numeric | Best bid and ask at close. |
| `trades` | integer | Number of trades (`negocios`). |
| `quantity` | numeric | Shares traded. |
| `volume` | numeric | Financial volume in BRL. |
| `isin` | text | ISIN as published. |
| `quotation_factor` | integer | `fator_cotacao` — the number of shares the quoted price refers to. |
| `close_unit` | number | `close / quotation_factor`, both published. |
| `adjusted` | boolean | Always `false`. |
| `source` | text | `b3_cotahist`. |
| `fetched_at` | timestamptz | When the pipeline ingested this row. View only. |
| `asset_class` | text | `equity`, `unit`, `bdr`, `fund_quota`, `index`, `right`, `bonus`, `cash_security`. `index` is an index line (IBOV11 — not an ETF); `right` and `bonus` are claims, not the security. |

<CodeGroup>

```bash curl
curl -s -G "$SILO_URL/quotes" \
  -H "apikey: $SILO_ANON_KEY" \
  --data-urlencode "select=ticker,trade_date,board,close,volume,adjusted,asset_class" \
  --data-urlencode "ticker=in.(PETR4,VALE3)" \
  --data-urlencode "board=eq.02" \
  --data-urlencode "trade_date=eq.2026-08-26"
```

```python Python
params = {
    "select": "ticker,trade_date,board,close,volume,adjusted,asset_class",
    "ticker": "in.(PETR4,VALE3)",
    "board": "eq.02",
    "trade_date": "eq.2026-08-26",
}
rows = requests.get(f"{URL}/quotes", headers=H, params=params).json()
```

```javascript JavaScript
const { data } = await supabase
  .from('quotes')
  .select('ticker, trade_date, board, close, volume, adjusted, asset_class')
  .in('ticker', ['PETR4', 'VALE3'])
  .eq('board', '02')
  .eq('trade_date', '2026-08-26')
```

</CodeGroup>

### `POST /rpc/quote_history`

One ticker's daily series over a window, ordered by `trade_date` ascending.

```sql
api.quote_history(p_ticker TEXT,
                  p_from   DATE DEFAULT CURRENT_DATE - 365,
                  p_to     DATE DEFAULT CURRENT_DATE,
                  p_board  TEXT DEFAULT NULL)
```

`p_ticker` is upper-cased and trimmed server-side. `p_board` null selects the board on the ticker's latest stored row.

Returns the view's columns minus `term_days` and `fetched_at`.

```bash
curl -s -X POST "$SILO_URL/rpc/quote_history" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_ticker":"PETR4","p_from":"2026-01-02","p_to":"2026-08-26"}'
```

<Warning>
  **One 1,000-row page, and it refuses above it** (`22023`) — you never receive a truncated series that looks complete. Roughly four years of one ticker fits in a page.

  Page it with `p_after: ""` then the last row's `trade_date`, or narrow the window:

  ```json
  { "p_ticker": "PETR4", "p_from": "2019-01-01", "p_after": "" }
  { "p_ticker": "PETR4", "p_from": "2019-01-01", "p_after": "2022-12-29" }
  ```

  The SDK walks it: `silo.iter_quote_history("PETR4", start="2019-01-01")`.
</Warning>

### `POST /rpc/quote_latest`

The most recent stored session for one ticker. At most one row, same columns as `quote_history`.

```sql
api.quote_latest(p_ticker TEXT,
                 p_board  TEXT DEFAULT NULL)
```

`p_board` null means "latest across all boards".

```python
rows = requests.post(
    f"{URL}/rpc/quote_latest", headers=H, json={"p_ticker": "PETR4"}
).json()
latest = rows[0] if rows else None      # empty list = we have no print
```

**Note**: "latest" means the latest session stored, not today — whatever the last successful COTAHIST ingest loaded. Check `trade_date` on the row and [`coverage`](/api-docs/coverage) for the dataset. A stale close is never advanced to today's date.

### Empty and error behavior

- **Unknown ticker → `200 []`.** Not a 404, and never a fabricated last close.
- **Known ticker, no sessions in the window** → also `200 []`. The two cases are indistinguishable from the response; use [`lookup`](/api-docs/lookup) to confirm the ticker exists.
- **Wrong board** is a common cause of a surprising empty result. Some papers do not print on `02` — retry with `"p_board": null`.
- A malformed date or filter returns `400`.

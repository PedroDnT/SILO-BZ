**Deployed preview.** SILO API v2 and MCP v2 are live. Use REST for application code or the data MCP for agents that call tools.

### 1. Discover the API

```bash
export SILO_V2="https://zcjbtpxuhdekpwcxmepn.supabase.co/functions/v1/silo-api/v2"
curl -fsS "$SILO_V2/"
```

The index lists all 14 resources with an example and a help link. For a resource's full parameter list, including options and defaults, use `?help=all`. The anonymous tier needs no key or sign-in.

### 2. Resolve an identifier and query data

```bash
curl -fsS --get "$SILO_V2/search" --data-urlencode "q=petrobras"
curl -fsS "$SILO_V2/prices?id=PETR4&kind=latest"
```

Use a ticker, CNPJ or other identifier from the search result that matches the entity you meant. `kind=latest` returns the raw close. Daily history defaults to split adjustment and excludes dividends.

### 3. Check coverage and completeness

```bash
curl -fsS "$SILO_V2/coverage?dataset=quotes"
```

Read `data_through` and `complete_through` before describing how current the data is. `landed_at` records ingestion, and `landed_git_sha` identifies the pipeline version. Keep the applied parameters from `meta.request` and the provenance from `meta.endpoint` when present.

Follow `next_page_url` for REST paging. In MCP, pass only its opaque `cursor` to the same tool. When `meta.tier_cap_reached` is true, the result is partial even if there is no next page.

### Connect an agent over MCP

Add the following URL to your client's remote MCP configuration using **Streamable HTTP**:

```text
https://zcjbtpxuhdekpwcxmepn.supabase.co/functions/v1/silo-mcp-v2
```

Discover tools with `tools/list`. The search example maps to `silo_search` with `{"q":"petrobras"}`; the quote maps to `silo_prices` with `{"id":"PETR4","kind":"latest"}`. Call `silo_coverage` with `{"dataset":"quotes"}` before making a freshness claim. Tool schemas list the arguments. Additional resource options go in `options`.

### Authenticate when a task needs more access

Use [SILO sign-in](https://silo-bz-deloslabs.vercel.app/signin.html) to obtain a user access token. The sign-in page shows a v1 example. For v2, send `Authorization: Bearer <access token>` to the v2 REST host or configure the same header in the MCP client. Keep the token in the client or server's secret store. An invalid or expired token is rejected on data calls. Signed-in access is required for `screens` and `portfolio`; Pro is granted separately.

If the gateway returns `over_limit`, narrow the window or filters based on the error. On `429`, honor `Retry-After`. Treat nulls, empty results, partial data and errors as different outcomes.

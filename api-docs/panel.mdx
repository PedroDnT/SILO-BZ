### Overview

`panel` is the primitive this API is built around. One row is an observation: `(id, date, metric, value)`.

That shape pulls B3 cash-market prints and fund fundamentals for the same window in one request. Pivot to a `dates × columns` matrix locally and run your reductions there — there is no server-side `corr`, `rank`, or regression.

```sql
api.panel(p_ids         TEXT[],
          p_metrics     TEXT[]  DEFAULT ARRAY['close','nav'],
          p_from        DATE    DEFAULT CURRENT_DATE - 365,
          p_to          DATE    DEFAULT NULL,  -- null = clamp fund rows to complete periods
          p_freq        TEXT    DEFAULT 'month',
          p_entity_type TEXT    DEFAULT NULL,  -- keep one fund family
          p_min_nav     NUMERIC DEFAULT NULL,  -- universe mode: latest NAV floor (BRL)
          p_min_months  INT     DEFAULT NULL,  -- universe mode: min observations of the first metric
          p_after       TEXT    DEFAULT NULL)  -- cursor: '' = first page, then the last row's key
```

**Note**: the grain is `(id, asset_class, date, metric)`. 385 CNPJs file under two families in the same month, so pivoting on `(id, date, metric)` alone raises or silently averages two vehicles. Pass `p_entity_type`, or keep `asset_class` in your pivot key.

### Parameters

<ParamField body="p_ids" type="string[]" required>
  Tickers, derivative codnegs, and/or CNPJs, mixed freely. Strip the non-digits: exactly 14 digits means CNPJ, anything else is a B3 code and is upper-cased. Blank entries are dropped.

  **Capped by tier: 3 ids anonymously, 50 signed in.** Over it raises `22023` (HTTP 400).
</ParamField>

<ParamField body="p_metrics" type="string[]" default='["close","nav"]'>
  Which metrics to emit, lower-cased and trimmed server-side. A name not in the table below is **silently ignored**, so a typo shows up as missing rows.
</ParamField>

<ParamField body="p_from" type="date" default="CURRENT_DATE - 365">
  Window start, inclusive. Snapped **down** to the first of the month for fund metrics; used as-is for quote metrics.
</ParamField>

<ParamField body="p_to" type="date" default="null">
  Window end, inclusive. Omitted, fund metrics end at each family's latest **complete** period, so a default panel never shows a fake trailing collapse; quote metrics still run to today. Pass an explicit `p_to` to get the window verbatim, partial months included. [`coverage`](/api-docs/coverage) reports each bound as `complete_through`.
</ParamField>

<ParamField body="p_freq" type="string" default="month">
  `month` or `day`. `day`, `d` and `daily` all mean daily; every other value falls back to `month` rather than erroring.
</ParamField>

<ParamField body="p_entity_type" type="string" default="null">
  Restrict the fund arms to `fi`, `fidc`, `fii`, `fip` or `fiagro`. Anything else raises `22023`. With `p_ids` empty it selects universe mode.
</ParamField>

<ParamField body="p_min_nav" type="numeric" default="null">
  Universe mode only. Keep funds whose latest non-null net assets in the window are at least this many BRL.
</ParamField>

<ParamField body="p_min_months" type="integer" default="null">
  Universe mode only. Keep funds with at least this many non-null observations of the first requested metric.
</ParamField>

<ParamField body="p_after" type="string" default="null">
  Paging cursor. `null` is whole-result mode and refuses above 1,000 rows. `''` asks for the first page. `'<date>|<id>|<metric>|<asset_class>'` from the last row you received asks for the next. A malformed cursor raises `22023`.
</ParamField>

### Universe mode

Leave `p_ids` empty and name a family with `p_entity_type`: the panel selects that family's funds itself, optionally floored by `p_min_nav` and `p_min_months`. Same long rows, nothing ranked server-side.

```json
{"p_ids": [], "p_metrics": ["delinquency", "nav"], "p_entity_type": "fidc",
 "p_from": "2025-09-01", "p_min_nav": 10000000, "p_min_months": 12, "p_after": ""}
```

**Note**: signed-in callers only — each page re-scans the family's window. `catalog().limits.tiers.<tier>.panel_universe` says which you are.

### Metrics

| Metric | Id type | Asset class | Grains | Source | Meaning |
| --- | --- | --- | --- | --- | --- |
| `close` | ticker, option, termo | equity, unit, bdr, fund_quota, cash_security, derivative | day, month | `b3_cotahist` | Unadjusted close. Monthly = last session of the month. |
| `volume` | ticker, option, termo | equity, unit, bdr, fund_quota, cash_security, derivative | day, month | `b3_cotahist` | Session financial volume in BRL. Monthly = the last session's volume, not a sum. |
| `close_unit` | ticker | equity, unit, bdr, fund_quota, cash_security | day, month | `b3_cotahist` | `close / quotation_factor` — price per single quoted unit. Use it to compare price levels across papers. Unadjusted. |
| `close_return` | ticker | equity, unit, bdr, fund_quota, cash_security | day, month | `b3_cotahist` | `p_t / p_(t-1) - 1` from unadjusted closes. Cash tickers only. |
| `nav` | cnpj | fi, fidc, fii, fip, fiagro | month | `cvm` | Fund net assets (`vl_patrim_liq`). |
| `quota` | cnpj | fi | month | `cvm` | Unit quota value. Comparable within a subclass only. |
| `delinquency` | cnpj | fidc, fiagro | month | `cvm` | Delinquent portfolio **value**, not a rate — divide by `nav` yourself. |
| `yield` | cnpj | fii | month | `cvm` | Monthly yield percentage as published. |
| `inflows` | cnpj | fi | month | `cvm` | Gross monthly subscriptions. |
| `redemptions` | cnpj | fi | month | `cvm` | Gross monthly redemptions. |
| `quotaholders` | cnpj | fi, fii | month | `cvm` | Number of unit-holders. Not filed by fidc, fiagro or fip. |
| `receivables` | cnpj | fidc | month | `cvm` | Receivables portfolio total (tab II `TOTAL`) — the denominator for a concentration ratio. See [FIDC](/api-docs/fidc). |
| `sacado_top1` | cnpj | fidc | month | `cvm` | Exposure to the largest debtor (tab VIII rank 1). Anonymized in the source. |
| `sacado_top25` | cnpj | fidc | month | `cvm` | Sum of the ranks the fund filed (1..n, n ≤ 25). Can exceed `receivables` for ~2% of funds — served as filed. |

Ask for a metric outside its families and you get **no rows** for those ids — not nulls, not zeros. The *Asset class* column is `catalog().applicability`.

### Response

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | text | Upper-cased B3 code, or a 14-digit CNPJ. |
| `id_type` | text | `ticker`, `option`, `termo`, or `cnpj`. |
| `asset_class` | text | For cash tickers the B3 type (`fund_quota` does not guess ETF vs FII); `derivative` for option and termo; for funds the vehicle's `entity_type`. |
| `date` | date | At `freq=month` always the **first day of the month**, for every id, so sources align. At `freq=day` the session date. |
| `metric` | text | One of the names above. |
| `value` | numeric | The observation. Nullable for `close` and `volume` only. |
| `source` | text | `b3_cotahist` or `cvm`. |

Ordered by `date`, then `id`, then `metric`.

### Paging

Rows are ordered by `(date, id, metric, asset_class)`, and that tuple is the cursor. Send `p_after: ""` for the first page, then the last row's key. A full page always has a next page; a short page is always the last.

```bash
after=""
while :; do
  page=$(curl -s -X POST "$SILO_URL/rpc/panel" -H "apikey: $SILO_ANON_KEY" \
    -H "Content-Type: application/json" \
    -d "{\"p_ids\":[\"PETR4\"],\"p_metrics\":[\"close\"],\"p_from\":\"2019-01-01\",\"p_freq\":\"day\",\"p_after\":\"$after\"}")
  echo "$page" | jq -c '.[]' >> panel.jsonl
  n=$(echo "$page" | jq 'length'); [ "$n" -lt 1000 ] && break
  after=$(echo "$page" | jq -r '.[-1] | "\(.date)|\(.id)|\(.metric)|\(.asset_class)"')
done
```

The SDK does this: `iter_panel(...)` / `panel_all(...)`. `Range` headers and `limit`/`offset` do not page an RPC call.

### Notes

- **Over 1,000 rows the panel refuses; it never trims.** Unpaged, a window over one page raises `22023` (HTTP 400) naming the fix. For scale: 1 id × 2 metrics × 12 months is 24 rows; 3 ids × 2 metrics × 5 years daily is ~7,500.
- **Nothing is forward-filled or interpolated.** A month a fund did not file is absent and stays absent. Correlate pairwise-complete; do not fill.
- **Two shapes of "no data".** Fund and derived metrics are emitted only when non-null, so a gap is an **absent row**. `close` and `volume` are emitted every session and can carry a JSON `null`.
- **`close_return` is unadjusted.** A 2:1 split reports roughly −50%. Treat jumps over ~40% as suspect until you have checked for a corporate action.
- **`close_return` needs a predecessor.** Monthly, only when the preceding row is the immediately preceding calendar month. Daily, against the previous stored session — a missing session makes the return span the gap. The first observation in a window is always absent; request more history than you analyze.
- **FIDC `delinquency` starts at 2025-01.** Null on every row through 2024-12 (`catalog().regime_breaks`).
- **`freq=day` is quotes only.** No CVM fundamental is published daily, so fund arms are not evaluated at a daily grain. Mix asset classes at `freq=month`.
- **Derivatives carry no `close_return`** and their real grain is wider than the panel's — COTAHIST keys them on board, and termo on term, so a within-session tie is cut deterministically (shortest term wins). For the full grain use [`option_history`](/api-docs/options) or [`termo_history`](/api-docs/termo).
- **An empty array means no observation matched** — unknown ids, no filings in the window, a metric that does not apply, or a silently ignored metric name. Confirm with [`lookup`](/api-docs/lookup) and [`coverage`](/api-docs/coverage).

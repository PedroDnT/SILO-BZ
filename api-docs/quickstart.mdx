### 1. Testing key

<Warning>
  The publishable key below is **shared** — everyone reading these docs has the same one. It identifies the project, not you.
</Warning>

```bash
export SILO_URL="https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1"
export SILO_ANON_KEY="sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437"
```

The env var omits the trailing slash so `"$SILO_URL/rpc/..."` joins cleanly.

**Sign in for a bigger ceiling.** [The sign-in page](https://silo-bz-deloslabs.vercel.app/signin.html) (GitHub) hands you a user JWT to send as `Authorization: Bearer <token>` alongside `apikey`. What each tier gets is one table on [Conventions & limits](/api-docs/conventions#authentication). Never invent or mint a key.

**Note**: ignore **Secret** (`sb_secret_…`) and legacy `service_role` — those bypass every boundary on these pages. Landing tables are unreachable with the publishable key: schema `api` is the entire public surface, and `Accept-Profile: public` answers 401 for every caller.

### 2. Send it on every request

The publishable key is **not** a JWT. Put it only on `apikey` — sending it as `Authorization: Bearer` returns `Invalid JWT`.

```
apikey: sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437
```

`Authorization` is only for a **user** session. The JS client (`createClient(url, publishableKey)`) sets `apikey` for you.

### 3. Your first call

Ask what the warehouse holds. `coverage` takes no arguments:

<CodeGroup>

```bash curl
curl -s -X POST "$SILO_URL/rpc/coverage" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```python Python
import os, requests

URL = "https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1"  # no trailing slash
KEY = os.environ.get("SILO_ANON_KEY", "sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437")
H = {"apikey": KEY}

print(requests.post(f"{URL}/rpc/coverage", headers=H, json={}).json())
```

```javascript JavaScript
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(
  'https://zcjbtpxuhdekpwcxmepn.supabase.co',
  process.env.SILO_ANON_KEY || 'sb_publishable__yfFQsykAglrvc9GS6_PYw_B24ex437',
  { db: { schema: 'api' } },
)

const { data, error } = await supabase.rpc('coverage')
console.log(data)
```

</CodeGroup>

The response is a plain JSON array — PostgREST has no envelope:

```json
[
  { "dataset": "quotes",   "as_of": "2026-08-26", "source": "b3_cotahist" },
  { "dataset": "funds",    "as_of": "2026-06-30", "source": "cvm" },
  { "dataset": "fund_nav", "as_of": "2026-06-01", "source": "cvm" }
]
```

**Note**: sample values throughout this documentation are illustrative shapes, not live prints. Call `coverage` to see what is actually loaded.

### 4. Read a view

Views are read with `GET` and PostgREST filter syntax:

<CodeGroup>

```bash curl
curl -s -G "$SILO_URL/quotes" \
  -H "apikey: $SILO_ANON_KEY" \
  --data-urlencode "select=ticker,trade_date,close,volume" \
  --data-urlencode "ticker=eq.PETR4" \
  --data-urlencode "board=eq.02" \
  --data-urlencode "order=trade_date.desc" \
  --data-urlencode "limit=5"
```

```python Python
params = {
    "select": "ticker,trade_date,close,volume",
    "ticker": "eq.PETR4",
    "board": "eq.02",
    "order": "trade_date.desc",
    "limit": 5,
}
rows = requests.get(f"{URL}/quotes", headers=H, params=params).json()
```

```javascript JavaScript
const { data } = await supabase
  .from('quotes')
  .select('ticker, trade_date, close, volume')
  .eq('ticker', 'PETR4')
  .eq('board', '02')
  .order('trade_date', { ascending: false })
  .limit(5)
```

</CodeGroup>

### 5. Call a function

Functions take **named arguments** in a JSON body, `POST /rpc/<name>`. Argument names are the SQL parameter names and all start with `p_`. Omit an argument to take its default.

<CodeGroup>

```bash curl
curl -s -X POST "$SILO_URL/rpc/panel" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "p_ids": ["PETR4", "VALE3"],
        "p_metrics": ["close_return"],
        "p_from": "2025-01-01",
        "p_to": "2026-06-30",
        "p_freq": "month"
      }'
```

```python Python
body = {
    "p_ids": ["PETR4", "VALE3"],
    "p_metrics": ["close_return"],
    "p_from": "2025-01-01",
    "p_to": "2026-06-30",
    "p_freq": "month",
}
rows = requests.post(f"{URL}/rpc/panel", headers=H, json=body).json()
```

```javascript JavaScript
const { data } = await supabase.rpc('panel', {
  p_ids: ['PETR4', 'VALE3'],
  p_metrics: ['close_return'],
  p_from: '2025-01-01',
  p_to: '2026-06-30',
  p_freq: 'month',
})
```

</CodeGroup>

```json
[
  { "id": "PETR4", "id_type": "ticker", "asset_class": "equity",
    "date": "2025-02-01", "metric": "close_return", "value": 0.0341, "source": "b3_cotahist" },
  { "id": "VALE3", "id_type": "ticker", "asset_class": "equity",
    "date": "2025-02-01", "metric": "close_return", "value": -0.0118, "source": "b3_cotahist" }
]
```

That is the whole shape of the API: views you `GET`, functions you `POST`.

### 6. Schema headers

Everything above assumes `api` is the **default** exposed schema. If the project exposes more than one and `api` is not first, name it explicitly:

- `Accept-Profile: api` on `GET`
- `Content-Profile: api` on `POST` (including `/rpc/`)

In `supabase-js` that is `createClient(url, key, { db: { schema: 'api' } })` or `supabase.schema('api')` per call. A `PGRST106` error means the schema is not exposed at all — fixed in Supabase Dashboard → Settings → API → **Exposed schemas**.

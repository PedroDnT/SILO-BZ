## What this is

**iliquid nightly** (SILO) is a headless ingestion pipeline that downloads, parses,
validates, and upserts Brazilian public financial data into a Supabase Postgres
database — CVM fund disclosures (FI, FIDC, FII, FIP, FIAGRO, SECURIT, plus listed-company
filings), BACEN time series, and B3 COTAHIST cash quotes. It exists for **financial
accountability** of the fund industry: NAV, delinquency, flows, and structural health.

The warehouse is readable **for testing** through schema `api` (PostgREST) with a
**shared publishable key**. There is **no RLS** on landing tables. When we go live,
callers will get a **key per user** (GitHub or email sign-in). This site documents
the read API. The human dashboard is
[https://iliquid-nightly.vercel.app/](https://iliquid-nightly.vercel.app/). **SILO**
is the GitHub repo: Actions ingest into Supabase, plus schema `api`.

## Base URL

```
https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1/
```

That is the only public HTTP surface. Views are `GET /<view>`; functions are
`POST /rpc/<function>`. Send the publishable key on `apikey` only — not as
`Authorization: Bearer`.

## The primitive is a panel

The main user is a researcher running correlation tests, factor models, and cross-asset
comparisons. The core endpoint is `panel` — one row is `(id, date, metric, value)` — so a
notebook can pull equity closes and fund fundamentals in a single call and reduce them
locally.

```bash
curl -s -X POST "https://zcjbtpxuhdekpwcxmepn.supabase.co/rest/v1/rpc/panel" \
  -H "apikey: $SILO_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"p_ids":["PETR4","VALE3"],"p_metrics":["close_return"],"p_freq":"month"}'
```

## What is exposed

| Resource | Kind | Read it for |
| --- | --- | --- |
| [`quotes`](/api-docs/quotes) | view + 2 functions | Unadjusted B3 cash prices, by ticker and session |
| [`funds`](/api-docs/funds) | view + 3 functions | Fund registry, profile, and monthly NAV/flows by CNPJ |
| [`panel`](/api-docs/panel) | function | Long `(id, date, metric, value)` observations across both |
| [`lookup`](/api-docs/lookup) | function | Resolve a ticker, ISIN, CNPJ, or name to an id |
| [`universe`](/api-docs/universe) | function | Enumerate ids by asset class |
| [`coverage`](/api-docs/coverage) | function | Latest date per dataset, before you claim freshness |

Landing tables (`cvm_*`, `b3_cotahist`, `cvm_ingest_log`) are **not** exposed. Schema `api`
is the boundary: English column names, ticker/CNPJ keys, and an explicit `adjusted = false`
flag so nobody mistakes these for split-adjusted prices.

## Rules the data follows

<Warning>
  These are non-negotiable properties of the contract, not best-effort behavior.

  - **Nothing is fabricated.** A ticker we have no row for returns no row — never a
    plausible last close.
  - **Missing observations stay missing.** No forward-fill, no interpolation, no
    carry-last-observation.
  - **`close_return` across a calendar gap is null**, not a two-month return.
    The ratio is of unadjusted closes: a 2:1 split reports roughly −50 %.
  - **`freq=day` is quotes only.** Mix equity with fund fundamentals on `freq=month`.
  - **Responses are hard-capped** (100,001 rows for `panel`, 5,001 for the series
    functions) so a too-large ask is visible, never silently truncated.
</Warning>

## Ingest

Ingestion runs on a GitHub Actions cron (`run_daily`) plus on-demand backfills
(`run_backfill`). There is **no ingest HTTP API** — this documentation covers the read side
only. The full operator guide lives in the repository:

- [README](https://github.com/PedroDnT/SILO-BZ/blob/main/README.md) — operator guide
- [docs/](https://github.com/PedroDnT/SILO-BZ/tree/main/docs) — architecture, data
  modeling, and the serving roadmap
